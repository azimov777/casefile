# 02. Список задач

## Цель

Первый рабочий экран: человек видит задачи с фильтрами и признаками и находит нужную
за один взгляд. Состояние фильтров живёт в адресе, страницы листаются курсором.

## Контекст

- `CONCEPT.md` раздел 3 (экран «Список задач») и 6.
- `GET /api/v1/tasks`: параметр `query` с языком запросов (`queue: DEMO and status: open
  and blocked: false`), либо структурные параметры `queue`, `status`, `assignee`, `tags`,
  `priority`, `blocked`, `open_questions`, `open_blocking_questions`, `text`; `sort`,
  `fields`, `limit`, `cursor`. Ошибка разбора запроса: `422` с позицией и допустимыми
  полями в `details`. В каждой строке объект `features`: `blocked`, `open_questions`,
  `open_blocking_questions`, `last_summary_at`. Подробности в `../tracker/docs/FRONTEND.md`,
  раздел «Строка списка».
- Очереди для селектора приходят из `bootstrap` (задача 01).

## Ограничения

- Один запрос на страницу списка; никаких запросов на строку.
- Фильтры отправляются структурными параметрами; поле «запрос» отправляет `query`
  и, если оно заполнено, имеет приоритет. Клиент язык запросов не разбирает и не
  проверяет: ошибку разбора показывает бэкенд, интерфейс подсвечивает позицию.
- Все фильтры, сортировка и курсор в адресе; перезагрузка страницы восстанавливает вид.
- Строка не редактируется, действий над задачей нет.

## Выход

- `pages/tasks` с таблицей: ключ, название, статус, исполнитель, приоритет, теги,
  признаки (значок «заблокирована», счётчик вопросов с выделением блокирующих,
  «последняя сводка N назад»), время обновления.
- `features/task-filters`: селектор очереди, статусов, исполнителя, тегов, приоритета,
  переключатели «заблокирована» и «есть открытые вопросы», поле текста и поле запроса
  на языке бэкенда.
- Сортировка по ключу, времени обновления, приоритету; кнопка «ещё» по курсору.
- `entities/task`: типы из контракта, запрос списка, представление строки.
- Состояния: загрузка, пусто с подсказкой, ошибка с текстом по коду, ошибка разбора
  запроса с позицией.
- Тесты страницы с MSW на все состояния; сквозной тест: фильтр по статусу `open`
  в демо даёт ожидаемые задачи. Заметки в `notes/`.

## Обзорные проверки

1. Открыть `/tasks?queue=DEMO&status=open`: таблица содержит только `open`-задачи демо; перезагрузка страницы сохраняет фильтры и выбранную очередь.
2. Ввести в поле запроса `status: opne`: под полем показана позиция ошибки и список допустимых значений из `details`, таблица не очищается.
3. Задача `DEMO-6` в таблице помечена «заблокирована», у `DEMO-4` показан один блокирующий вопрос; значения равны `features` из карточки бэкенда.
4. Смена сортировки и «ещё» меняют адрес; вкладка, открытая по скопированному адресу, показывает то же самое.
5. Журнал сети при открытии страницы: ровно один запрос к `/api/v1/tasks` на страницу и ни одного к `/api/v1/tasks/{key}`.
6. Пустой результат показывает текст «Задач по этим условиям нет» и кнопку сброса фильтров.
7. `pnpm check` и `pnpm e2e` зелёные; всё запущенное погашено.
