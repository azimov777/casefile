# 03. Доска

## Цель

Дать человеку взгляд на процесс целиком: задачи одной очереди по столбцам статусов,
по одному на каждый статус. Это режим отображения того же списка, а не отдельная сущность.

## Контекст

- `CONCEPT.md` раздел 3; `../tracker/docs/FRONTEND.md`, раздел «Доска без доски».
- Данные и фильтры из задачи 02: тот же запрос `GET /api/v1/tasks` с фильтром по очереди,
  столбцы по значению `status`. Порядок столбцов совпадает с порядком значений
  в перечислении статуса сгенерированного клиента (`openapi.ts`): сейчас `backlog`,
  `open`, `in_progress`, `review`, `done`, `cancelled`.
- Статус `review` снимается задачей TRK-4 по решению владельца от 2026-09-05:
  обзорные проверки становятся частью работы в `in_progress`, статусов остаётся
  пять. После TRK-4 контракт `../tracker/openapi.json` меняется и клиент
  перегенерируется `pnpm gen:api`; доска не должна требовать правки ни до, ни после
  этого (выявлено в TRK-4).

## Ограничения

- Перетаскивания нет: переходы делают агенты. Карточка кликабельна и ведёт в карточку
  задачи.
- Ранжирования и лимитов нет; внутри столбца порядок по времени обновления, свежие сверху.
- Режим переключается в адресе (`view=board`), фильтры общие со списком, кроме статуса:
  на доске он всегда «все».
- Столбцы `done` и `cancelled` свёрнуты по умолчанию и показывают число задач.
- Перечень и порядок столбцов не зашивать в код и тесты доски: брать из перечисления
  статуса сгенерированного клиента, чтобы снятие статуса `review` (TRK-4) прошло
  перегенерацией клиента без правки доски. Зашить можно только человеческие
  названия столбцов и признак «свёрнут по умолчанию», и то словарём по значению
  статуса, а не списком (выявлено в TRK-4).

## Выход

- Режим доски в `pages/tasks`, переключатель «таблица / доска», карточка задачи
  на доске: ключ, название, исполнитель, признаки, приоритет.
- Подгрузка по курсору внутри доски: если страница списка не вместила все задачи
  очереди, внизу доски кнопка «ещё», а столбцы честно помечены «показано N из ?».
- Тесты страницы и сквозной тест на демо. Заметки в `notes/`.

## Обзорные проверки

1. `/tasks?queue=DEMO&view=board` показывает по одному столбцу на каждое значение перечисления статуса в `openapi.ts` (шесть до TRK-4, пять после); в каждом ровно те задачи демо, чей статус совпадает с заголовком.
2. Столбцы `done` и `cancelled` свёрнуты и показывают число; клик раскрывает.
3. Клик по карточке ведёт на `/tasks/DEMO-6`; в адресе доски после возврата назад сохранён `view=board`.
4. Фильтр по исполнителю на доске оставляет в столбцах только его задачи; переключение в таблицу сохраняет фильтр.
5. Журнал сети: один запрос списка на отрисовку доски.
6. В коде и тестах доски нет зашитого перечня статусов: в срезе доски (`src/pages/tasks` и всё, что заведено для неё) строка `review` не встречается, а тест доски строит ожидаемый набор столбцов из перечисления клиента, а не из списка в тесте (выявлено в TRK-4).
7. `pnpm check` и `pnpm e2e` зелёные; всё запущенное погашено.
