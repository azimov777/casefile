# 03. Доска

## Цель

Дать человеку взгляд на процесс целиком: задачи одной очереди по шести столбцам
статусов. Это режим отображения того же списка, а не отдельная сущность.

## Контекст

- `CONCEPT.md` раздел 3; `../tracker/docs/FRONTEND.md`, раздел «Доска без доски».
- Данные и фильтры из задачи 02: тот же запрос `GET /api/v1/tasks` с фильтром по очереди,
  столбцы по значению `status`. Порядок статусов: `backlog`, `open`, `in_progress`,
  `review`, `done`, `cancelled`.

## Ограничения

- Перетаскивания нет: переходы делают агенты. Карточка кликабельна и ведёт в карточку
  задачи.
- Ранжирования и лимитов нет; внутри столбца порядок по времени обновления, свежие сверху.
- Режим переключается в адресе (`view=board`), фильтры общие со списком, кроме статуса:
  на доске он всегда «все».
- Столбцы `done` и `cancelled` свёрнуты по умолчанию и показывают число задач.

## Выход

- Режим доски в `pages/tasks`, переключатель «таблица / доска», карточка задачи
  на доске: ключ, название, исполнитель, признаки, приоритет.
- Подгрузка по курсору внутри доски: если страница списка не вместила все задачи
  очереди, внизу доски кнопка «ещё», а столбцы честно помечены «показано N из ?».
- Тесты страницы и сквозной тест на демо. Заметки в `notes/`.

## Обзорные проверки

1. `/tasks?queue=DEMO&view=board` показывает шесть столбцов; в каждом ровно те задачи демо, чей статус совпадает с заголовком.
2. Столбцы `done` и `cancelled` свёрнуты и показывают число; клик раскрывает.
3. Клик по карточке ведёт на `/tasks/DEMO-6`; в адресе доски после возврата назад сохранён `view=board`.
4. Фильтр по исполнителю на доске оставляет в столбцах только его задачи; переключение в таблицу сохраняет фильтр.
5. Журнал сети: один запрос списка на отрисовку доски.
6. `pnpm check` и `pnpm e2e` зелёные; всё запущенное погашено.
