# 07. Живой поток

## Цель

Экран не устаревает: один поток ленты журнала на приложение, по кадрам обновляются
список, доска, карточка, дело и счётчик вопросов. Соединение переживает обрывы
и продолжается с места разрыва.

## Контекст

- `CONCEPT.md` раздел 5; `../tracker/docs/FRONTEND.md`, раздел «Живой поток».
- `GET /api/v1/journal/stream` с параметрами `after`, `queue`, `types`; кадры SSE
  с `id:` равным `seq`, `event:` равным типу записи, `data:` схемы `EntryRead`
  с `task_key`; продолжение по заголовку `Last-Event-ID` или параметру `after`.
  Заголовок авторизации требует `fetch`-клиента (`@microsoft/fetch-event-source`).
- Ключи запросов TanStack Query из задач 02–06.

## Ограничения

- Один поток на вкладку, открывается после входа, закрывается при выходе; параллельных
  потоков на страницы нет.
- Кадр не пишется в кеш руками: по `task_key` и типу записи инвалидируются ключи
  запросов (`['task', key]`, `['entries', key]`, `['tasks']`, `['questions']`,
  `['bootstrap']` для `question` и `answer`). Исключение: опись открытой карточки
  может дописать строку из кадра, чтобы не дёргать пакет на каждую запись.
- При обрыве: экспоненциальная пауза до 30 секунд, продолжение с последнего `seq`,
  индикатор «соединение потеряно, переподключаюсь» в шапке. При `401` поток
  закрывается и работает общая обработка входа.
- Вкладка в фоне: поток не закрывать, но инвалидации копить и применять при возврате.

## Выход

- `features/live-journal`: клиент потока, курсор `seq` в памяти, карта «тип записи →
  какие ключи инвалидировать», индикатор соединения в шапке.
- Уведомление в шапке «новый вопрос вам» по кадру `question` с адресатом, равным
  текущему участнику.
- Тесты клиента потока с подменой `fetch` (кадры, обрыв, продолжение с `Last-Event-ID`,
  `401`), сквозной тест: изменение задачи через API бэкенда отражается в открытом
  списке без перезагрузки. Заметки в `notes/live.md`.

## Обзорные проверки

1. Открыт список `DEMO`; через API бэкенда задача переводится в другой статус: строка в таблице меняется в пределах двух секунд без перезагрузки; журнал сети показывает один повторный запрос списка, а не серию.
2. Открыта карточка `DEMO-3`; через API подшита запись `note`: опись пополнилась строкой, пакет не перезапрашивался.
3. Бэкенд остановлен на десять секунд и поднят: индикатор в шапке показал потерю и восстановление; кадры, подшитые в паузу, не пропущены (записи, сделанные через API во время паузы, появились после восстановления).
4. Через MCP задан вопрос текущему участнику: в шапке появилось уведомление, счётчик вырос без перезагрузки.
5. На вкладку приложения приходится ровно одно соединение к `journal/stream` при переходах между страницами.
6. `pnpm check` и `pnpm e2e` зелёные; всё запущенное погашено.
