# 09. Устойчивость: граница ошибок и повтор запроса

## Цель

Сделать так, чтобы интерфейс не показывал человеку белый экран и не заводил его в тупик.
Сейчас исключение в любом компоненте роняет всё приложение без единого слова, а отказавший
запрос человек может только перезагрузить страницу целиком. Задача даёт два общих кирпича,
которыми потом пользуются все экраны: границу ошибок приложения и состояние запроса
с повтором.

Брать её можно сразу после 01: чем раньше кирпичи появятся, тем меньше экранов придётся
переделывать.

## Контекст

- `CONVENTIONS.md`, раздел «Интерфейс»: «Пустые и ошибочные состояния у каждого запроса
  нарисованы явно; спиннер без текста не считается состоянием».
- `CONCEPT.md`, раздел 6: «Ошибка это код» — текст выбирается по `error.code`
  из `shared/errors`, `details.fields` показываются у полей формы.
- Уже есть: `ApiError` с кодом, статусом и подробностями (`shared/api`), словарь текстов
  (`shared/errors`), кирпич `Callout` (`shared/ui`), политика повторов TanStack Query
  (`app/config/query-client.ts`: отказ 4xx не повторяется).
- Экран, на котором это видно уже сейчас: шапка (`app/layouts/app-header.tsx`) рисует отказ
  `bootstrap` строкой без возможности что-либо сделать.

## Ограничения

- Граница ошибок ловит падения отрисовки, а не отказы запросов: у запросов своё состояние.
  Одно не подменяет другое.
- Повтор — действие человека, а не автоматика: молчаливых повторов сверх политики
  `query-client.ts` не добавлять.
- Технический текст исключения человеку не показывается; он уходит в консоль браузера.
  На экране — что случилось и что можно сделать.
- Новых зависимостей не добавлять: граница ошибок пишется на `class ... extends Component`,
  библиотека для этого не нужна.

## Выход

- Граница ошибок в `app`: перехватывает падение отрисовки, показывает экран с объяснением
  и кнопкой «Перезагрузить», пишет исключение в консоль. Оболочка приложения и каждая
  страница внутри неё продолжают работать, когда падает соседняя.
- Кирпич состояния запроса в `shared/ui`: загрузка с текстом, честная пустота, отказ
  с текстом по коду и кнопкой «Повторить». Кнопка зовёт `refetch`, а не перезагружает
  страницу.
- Шапка и заглушка списка переведены на этот кирпич: отказ `bootstrap` можно повторить,
  не теряя введённого.
- Тесты: страничный на падение компонента внутри оболочки (шапка жива, экран объяснён),
  страничный на отказ запроса и удачный повтор, модульный на выбор текста по коду.
- Карты `AGENTS.md` затронутых папок; заметки, если что-то окажется неочевидным.

## Обзорные проверки

1. Компонент, брошенное исключение в котором раньше давало белый экран, теперь даёт экран с объяснением и кнопкой «Перезагрузить»; текст исключения виден в консоли браузера, но не на странице.
2. Отказ `bootstrap` в шапке показывает русский текст по коду и кнопку «Повторить»; после починки бэкенда повтор наполняет шапку без перезагрузки страницы.
3. Отказ с неизвестным кодом показывает фразу бэкенда и сам код, а не «что-то пошло не так».
4. `pnpm check` и `pnpm e2e` зелёные целиком; `axe` не находит новых нарушений serious.
5. После работы dev-сервер, Playwright и контуры Docker погашены.
