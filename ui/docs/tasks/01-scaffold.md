# 01. Каркас: репозиторий, клиент API, оболочка, вход

## Цель

Заложить проект так, чтобы следующие задачи добавляли экраны, а не инфраструктуру:
инструменты, структура по слоям, сгенерированный клиент, оболочка приложения с темой
и навигацией, вход по токену и первый экран из `bootstrap`, разбор оболочки ответов
и словарь ошибок, сборка в Docker.

## Контекст

- `CONCEPT.md` разделы 2, 3, 6; `CONVENTIONS.md` целиком.
- Контракт: `../tracker/openapi.json`, карта `../tracker/docs/FRONTEND.md`. Бэкенд
  поднимается по `../tracker/README.md`: контур, миграции, `init` печатает токен,
  `demo` наполняет очередь `DEMO`.
- Авторизация: `Authorization: Bearer trk_...`; `401` при плохом токене; `403` при
  выходе за набор токена. `GET /api/v1/bootstrap` отдаёт `participant`, `queues`,
  `open_questions`.
- Коды ошибок бэкенда: `../tracker/docs/ERRORS.md`. Оболочка: `data` / `data` + `meta`
  / `error` с `code`, `message`, `details`.

## Ограничения

- Стек и структура строго по `CONVENTIONS.md`; библиотек компонентов нет.
- Сгенерированный `openapi.ts` коммитится; тест сверяет его с `../tracker/openapi.json`
  и падает при расхождении с понятным сообщением «перегенерируй `pnpm gen:api`».
- Токен только в `localStorage` и заголовке; в адрес страницы не попадает.
- Никаких экранов сверх входа и пустой оболочки: список, карточка и прочее
  в следующих задачах. Пункты меню на них можно оставить неактивными.

## Выход

- `package.json` со скриптами `dev`, `build`, `check`, `test`, `e2e`, `gen:api`;
  ESLint, Prettier, `tsc`, `steiger`, Vitest, Playwright настроены; `.nvmrc`.
- `src/` по слоям: `app` (маршруты, провайдеры, тема, шапка с именем участника
  и счётчиком вопросов), `pages/login`, `shared/api` (сгенерированные типы, клиент
  `openapi-fetch`, разбор оболочки, перехватчик токена, обработка `401`),
  `shared/errors` (словарь кодов из `ERRORS.md` на русском), `shared/styles`
  (переменные темы, светлая и тёмная, сброс).
- Экран входа: поле токена, проверка через `bootstrap`, сообщение об ошибке по коду,
  переход на `/tasks` (пока заглушка «список появится в задаче 02»).
- `docker/Dockerfile` (сборка и nginx), `docker-compose.yml`, который поднимает интерфейс
  и бэкенд из `../tracker` для Playwright; один сквозной тест: вход с токеном демо
  и шапка с именем участника.
- README с командами запуска; `AGENTS.md` всех папок; заметки о неочевидном
  в `notes/tooling.md`.

## Обзорные проверки

1. `pnpm gen:api` на текущем `../tracker/openapi.json` не меняет закоммиченный `openapi.ts`; после правки любой строки `openapi.ts` тест сверки падает с сообщением про `pnpm gen:api`.
2. `pnpm check` зелёный; импорт из `pages` в `shared` или между двумя срезами одного слоя ломает `pnpm check` сообщением `steiger`.
3. Вход с неверным токеном показывает русский текст для `unauthorized`, токен в `localStorage` не сохраняется; вход с токеном из `init` показывает имя участника и число открытых вопросов из `bootstrap`.
4. При `401` на любом запросе после входа приложение сбрасывает токен и открывает `/login` с пояснением.
5. Тема следует `prefers-color-scheme`: в обоих режимах контраст текста и фона проходит `axe` без нарушений уровня serious.
6. `docker compose up` из этого репозитория поднимает интерфейс и бэкенд; `pnpm e2e` проходит сквозной тест входа против демо-данных.
7. Токен не встречается ни в адресной строке, ни в журнале сети в параметрах запросов: только в заголовке.
8. После работы dev-сервер, Playwright и контуры Docker погашены.
