# 04. Карточка задачи

## Цель

Главный экран: человек открывает незнакомую задачу и за одну прокрутку понимает,
что это, где стоит, что мешает и что сказал последний агент. Всё из одного запроса
пакета преемника; тела записей подгружаются по клику.

## Контекст

- `CONCEPT.md` разделы 3 и 4; `../tracker/docs/FRONTEND.md`, раздел «Карточка задачи
  одним запросом».
- `GET /api/v1/tasks/{key}` отдаёт `task`, `links`, `features`, `summary`, `questions`,
  `index`, `transitions` (схема `TaskPackageRead`). `GET /api/v1/tasks/{key}/entries?nos=3,7`
  отдаёт тела записей. Схема записи `EntryRead`: объединение по полю `type`
  с типизированным `payload` на каждый тип.
- Пять разделов задачи в markdown; `checks` это список строк с нумерацией с единицы.

## Ограничения

- Один запрос пакета на открытие карточки; тела записей только по клику и только те,
  что попросили (`nos`).
- Кнопок переходов и правки нет; `transitions` показывается как справка «куда задача
  может уйти по таблице».
- Markdown рисуется без HTML; ссылки `TRK-42#12` и `TRK-42` превращаются в ссылки
  приложения (в описи и в телах).
- Форма ответа на вопрос делается в задаче 06; здесь открытые вопросы только
  показываются.

## Выход

- `pages/task`: шапка (ключ, название, статус, приоритет, исполнитель, теги, очередь),
  блок признаков, последняя сводка четырьмя частями, открытые вопросы, пять разделов
  с нумерованными проверками, связи с обеих сторон и статусом другой стороны, опись дела
  таблицей (номер, тип, автор, время, заголовок) с раскрытием тела по клику
  и представлением по типу (`entities/entry`).
- Пустые состояния: сводки ещё нет, вопросов нет, связей нет, дело пусто.
- Ошибки: `task_not_found` с предложением вернуться к списку.
- Тесты страницы с MSW, сквозной тест на `DEMO-6` и `DEMO-4` из демо. Заметки в `notes/`.

## Обзорные проверки

1. `/tasks/DEMO-6` показывает статус `review`, признак «заблокирована» со ссылкой на `DEMO-2`, сводку из четырёх частей, опись из семи записей; журнал сети содержит один запрос пакета и ни одного к `entries`.
2. Клик по записи `verdict` в описи подгружает тело одним запросом `entries?nos=6` и показывает номер проверки, текст проверки из `checks`, исход и доказательство.
3. `/tasks/DEMO-4` показывает открытый блокирующий вопрос целиком, без клика.
4. В теле записи ссылка `DEMO-2` кликабельна и ведёт на карточку `DEMO-2`; ссылка вида `DEMO-6#4` ведёт на запись 4 и раскрывает её.
5. Раздел «Обзорные проверки» показан нумерованным списком с единицы; номера совпадают с `check_no` в вердиктах.
6. `/tasks/DEMO-999` показывает текст для `task_not_found` и ссылку на список.
7. `pnpm check` и `pnpm e2e` зелёные; всё запущенное погашено.
