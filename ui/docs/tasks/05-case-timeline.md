# 05. Дело лентой

## Цель

Дать человеку прочитать дело целиком, когда описи и сводки мало: все записи по порядку,
каждая нарисована по своему типу, с фильтром по типам и переходами по ссылкам.

## Контекст

- `CONCEPT.md` раздел 4 (таблица «как показать» по типам).
- `GET /api/v1/tasks/{key}/entries` с параметрами `types`, `after_no`, `limit`, `cursor`;
  `GET /api/v1/tasks/{key}/entries/{no}` для одной записи. Типы и `payload`
  в `../tracker/docs/CONCEPT.md`, 3.4: `summary` (четыре части), `question`
  (`addressees`, `blocking`), `answer` (`question_no`), `verdict` (`check_no`, `outcome`),
  `status_changed` (`from`, `to`, `reason`), `section_changed` (`field`, `before`,
  `after`), `assignee_changed`, `link_added` / `link_removed` (`kind`, `other`).
- Представление одной записи `entities/entry` сделано в задаче 04; здесь оно
  используется в ленте и дополняется типами, которых в описи не открывали.

## Ограничения

- Страницы по курсору бэкенда; ленту не загружать целиком одним запросом.
- Ответы группируются под своим вопросом по `question_no`; отдельно в ленте ответ
  не повторяется.
- `section_changed` показывает «было / стало» как сравнение строк; для `checks`
  как сравнение списков.
- Записи неизменяемы; никаких действий над записью, кроме копирования ссылки `TRK-42#12`.

## Выход

- `pages/case` по адресу `/tasks/:key/case`: лента с фильтром по типам (группы «записи
  агента», «служебные», отдельные типы), кнопка «ещё», переход к записи по номеру
  из адреса (`#12` прокручивает и подсвечивает).
- Представления всех пятнадцати типов в `entities/entry`; ссылки в телах
  и в `refs` кликабельны; у `artifact` указатели вида пути или адреса показаны
  как ссылки.
- Кнопка «скопировать ссылку на запись» у каждой записи.
- Тесты представления каждого типа на данных демо; сквозной тест: лента `DEMO-4`
  с фильтром `question` показывает вопрос и его ответы под ним. Заметки в `notes/`.

## Обзорные проверки

1. `/tasks/DEMO-1/case` показывает все записи дела `DEMO-1` в порядке `no`; фильтр «служебные» оставляет только `created`, `status_changed`, `section_changed`, `assignee_changed`, `link_*`.
2. У записи `section_changed` по `goal` видно «было / стало»; у `status_changed` показана причина, если она есть.
3. Ответы на вопрос в `DEMO-4` показаны под вопросом, а не отдельными записями; фильтр `answer` показывает их отдельно.
4. Переход по адресу `/tasks/DEMO-6/case#4` прокручивает к записи 4 и подсвечивает её.
5. Все пятнадцать типов из демо отрисованы своими представлениями: в снимках тестов нет записи, показанной «сырым» JSON.
6. Журнал сети при открытии ленты: один запрос `entries` на страницу.
7. `pnpm check` и `pnpm e2e` зелёные; всё запущенное погашено.
