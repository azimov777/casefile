# 06. Открытые вопросы и ответ

## Цель

То единственное, что человек делает в трекере: увидеть адресованные ему вопросы
и ответить. Входящая со счётчиком в шапке, форма ответа в карточке и во входящей.

## Контекст

- `CONCEPT.md` разделы 2, 3, 6; `../tracker/docs/FRONTEND.md`, разделы «Роль
  человека» и «Оболочка ответа и ошибки» (про ответ на вопрос).
- `GET /api/v1/questions` с параметрами `addressee`, `queue`, `blocking`, `open`,
  `limit`, `cursor`; по умолчанию открытые вопросы текущего участника.
  `POST /api/v1/tasks/{key}/entries` с телом `{"type": "answer", "body": ...,
  "payload": {"question_no": N}, "refs": [...]}`; заголовок `Idempotency-Key`
  на создающих вызовах. Ошибки полей приходят как `entry_fields_invalid`
  с `details.fields`.
- Число открытых вопросов в шапке приходит из `bootstrap` (задача 01).

## Ограничения

- Ответ отправляется с `Idempotency-Key` (UUID на попытку отправки), чтобы повтор
  по сети не создал два ответа.
- После ответа вопрос исчезает из входящей и из блока открытых вопросов карточки;
  счётчик в шапке уменьшается. До задачи 07 это делается инвалидацией запросов,
  а не правкой кеша руками.
- Черновик ответа не теряется при случайной навигации: хранится в `sessionStorage`
  по ключу вопроса до отправки.
- Никаких других записей от человека (заметок, вопросов) в этой задаче.

## Выход

- `pages/questions`: список открытых вопросов текущего участника с фильтрами
  «только блокирующие» и «очередь», строка: задача, заголовок, автор, время, признак
  «блокирующий», кнопка «ответить».
- `features/answer-question`: форма с markdown-полем, предпросмотром, полем ссылок
  `refs`, отправкой с ключом идемпотентности, показом ошибок по `details.fields`;
  встраивается в карточку (задача 04) под каждым открытым вопросом и во входящую.
- Счётчик в шапке обновляется после ответа.
- Тесты формы с MSW (успех, `entry_fields_invalid`, сеть оборвалась и повтор с тем же
  ключом), сквозной тест: ответить на вопрос `DEMO-4` из демо. Заметки в `notes/`.

## Обзорные проверки

1. Вход владельцем демо: в шапке число вопросов равно `open_questions` из `bootstrap`; `/questions` показывает вопрос из `DEMO-4` с признаком «блокирующий».
2. Ответ на него из входящей: запрос уходит с `Idempotency-Key`, после `201` вопрос исчезает из списка, счётчик в шапке уменьшается на один, в карточке `DEMO-4` блок открытых вопросов пуст, а в описи появилась запись `answer`.
3. Имитация обрыва сети после отправки и повтор: на бэкенде ровно одна запись `answer` (проверяется через `entries?types=answer`).
4. Ответ с пустым телом не отправляется: подсказка у поля; ошибка `entry_fields_invalid` от бэкенда показывается у соответствующего поля.
5. Начатый черновик переживает переход на другую страницу и возврат.
6. `pnpm check` и `pnpm e2e` зелёные; всё запущенное погашено.
