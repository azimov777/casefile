# Порядок выполнения задач

Задачи лежат в `tasks/`. Номер файла — рекомендуемый порядок, реальное ограничение —
зависимости: задачу можно брать, когда выполнены все, от которых она зависит.

## Граф зависимостей

```
01 Каркас: репозиторий, клиент API, оболочка, вход
 ├─ 09 Устойчивость: граница ошибок и повтор запроса
 └─ 02 Список задач
     ├─ 03 Доска
     └─ 04 Карточка задачи
         ├─ 05 Дело лентой
         └─ 06 Открытые вопросы и ответ
             └─ 07 Живой поток  (нужны также 02, 04)
                 └─ 08 Поставка: сквозные тесты, доступность, README
```

## Линейный порядок запуска агентов

| Шаг | Задача | Статус | Комментарий |
|---|---|---|---|
| 1 | 01 Каркас | ✅ | Инструменты, FSD, сгенерированный клиент, оболочка, вход по токену, `bootstrap`, словарь ошибок, Docker |
| 2 | 02 Список задач | ✅ | Таблица с признаками, фильтры и язык запросов, сортировка, курсор, состояние в адресе |
| 3 | 04 Карточка задачи | ✅ | Пакет преемника: разделы, связи, признаки, сводка, вопросы, опись с подгрузкой тел |
| 4 | 03 Доска | ✅ | Режим списка: столбец на каждое значение статуса из контракта |
| 5 | 05 Дело лентой | ⬜ | Все записи по типам, фильтр, ссылки `TRK-42#12` |
| 6 | 06 Вопросы и ответ | ⬜ | Входящая, форма ответа, счётчик в шапке |
| 7 | 07 Живой поток | ⬜ | SSE с `Last-Event-ID`, инвалидация по кадрам, индикатор соединения |
| 8 | 08 Поставка | ⬜ | Playwright против демо в Docker, `axe`, README, сборка |

Вне линейного порядка: **09 Устойчивость** ✅ — граница ошибок приложения и кирпич
состояния запроса с повтором (`shared/ui/query-state.tsx`) сделаны до того, как экраны
разошлись каждый со своим состоянием отказа; новые экраны берут их готовыми.

## Что можно делать параллельно

После 02 независимы 03 и 04. После 04 независимы 05 и 06. Всё остальное последовательно:
01 закладывает структуру, 07 трогает все страницы, 08 закрывает целое.

## Точки, где стоит остановиться и посмотреть результат

- **После 02**: первый живой экран. Открыть демо-очередь и проверить, читается ли таблица
  с признаками, удобен ли язык запросов человеку.
- **После 04**: главный экран. Дать человеку незнакомую задачу из демо и посмотреть,
  понимает ли он ситуацию по сводке и описи без чтения всего дела.
- **После 06**: человек может делать то единственное, что от него нужно: ответить.
  Задать вопрос через MCP агентом и ответить из интерфейса.
- **После 07**: экран живёт. Подвигать задачу агентом и смотреть, как меняется таблица
  без перезагрузки.
