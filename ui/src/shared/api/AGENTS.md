# src/shared/api

Всё общение с бэкендом. Ручных типов ответов здесь нет: они берутся из контракта.

## Файлы

- `openapi.ts` — сгенерирован `pnpm gen:api` из `../openapi.json`, правке не подлежит;
  расхождение с контрактом ловит `openapi.contract.test.ts`
- `client.ts` — клиент `openapi-fetch`, перехватчик токена и обработка `401`
- `envelope.ts` — разбор оболочки `data` / `data` + `meta`; любой сбой становится `ApiError`
- `error.ts` — `ApiError`: код, статус, подробности, замечания по полям
- `token.ts` — два источника ключа (установка и человек), старшинство, подписка на смену
- `install-config.ts` — чтение `GET /config.json`: ключ от установки и его перечитывание после `401`
- `index.ts` — публичный интерфейс сегмента
- `openapi.contract.test.ts` — сверка сгенерированного клиента с контрактом бэкенда
- `frontend-doc.contract.test.ts` — сверка `docs/FRONTEND.md` с контрактом бэкенда: пути и коды ошибок
- `envelope.test.ts` — разбор оболочки ответа и превращение любого сбоя в `ApiError`
- `error.test.ts` — разбор тела ошибки и замечаний по полям
- `token.test.ts` — хранилище токена и оповещение подписчиков
- `install-config.test.ts` — что читается ключом, что читается его отсутствием и сколько
  раз конфигурацию спрашивают
