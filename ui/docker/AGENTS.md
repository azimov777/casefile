# docker

Образ интерфейса. Контур сквозных тестов описан в `docker-compose.yml` в корне
интерфейса, установка из готовых образов — в `../docker-compose.prod.yml`.

## Файлы

- `Dockerfile` — сборка статики в Node и отдача её через nginx; адрес бэкенда
  задаётся переменной `TRACKER_API_URL` при запуске, а не при сборке
- `nginx.conf.template` — одностраничное приложение и проксирование `/api` на бэкенд;
  буферизация для `/api` выключена ради живого потока; у `/config.json` свой `location`
  с `404` и `no-store`, в режиме пароля — за `auth_request` на сеанс в API и с отказом
  `401 {"login":"password"}`. Шаблон разворачивает штатный скрипт образа nginx при
  старте контейнера
- `access-mode.sh` — шаг старта контейнера до ключа: по `TRACKER_UI_LOGIN` и
  `TRACKER_UI_BIND` пишет правило `Host` и условие выдачи `/config.json`, которые
  подключает шаблон; без пароля порт не на петле — отказ подняться
- `config-json.sh` — шаг старта контейнера: кладёт рядом со статикой `/config.json`
  с ключом установки из `TRACKER_UI_TOKEN` (контур сквозных тестов) или из файла
  `TRACKER_UI_TOKEN_FILE` (установка), в режиме пароля — с полем `login`. Нет ни того ни
  другого — файла нет, и это норма: интерфейс покажет экран входа
