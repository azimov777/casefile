# tracker-ui

Интерфейс человека для трекера задач, которые ведут агенты. Отдельный проект; бэкенд
и контракт API живут в репозитории `tracker` рядом.

**Перед любой работой в репозитории:** прочитать `docs/CONCEPT.md` (что строим),
`docs/CONVENTIONS.md` (как строим и обязательный протокол выполнения задачи) и заметки
в `docs/notes/` по своей области. Задания в `docs/tasks/`.

**Очередь этого репозитория в трекере: `UI`.** Задачи по интерфейсу ведутся там; ключ
задачи `UI-N` называет этот репозиторий, `TRK-N` — репозиторий бэкенда `tracker`.

Команды запуска и проверок — в `README.md`.

## Папки

- `docs/` — концепция, соглашения, дорожная карта, задания для агентов, накопленные заметки
- `src/` — исходный код по слоям Feature-Sliced Design
- `testing/` — обвязка модульных и страничных тестов: подмена API, рендер приложения
- `e2e/` — сквозные сценарии Playwright и подъём контура для них
- `docker/` — образ интерфейса и конфигурация nginx

## Файлы

- `README.md` — что это, с чего начать, команды разработки, проверок и сборки
- `package.json` — зависимости и скрипты; версия pnpm задана `packageManager`
- `pnpm-lock.yaml` — закреплённые версии зависимостей
- `pnpm-workspace.yaml` — какие зависимости вправе запускать сборочные скрипты
- `index.html` — страница-оболочка Vite
- `vite.config.ts` — сборка, Tailwind плагином, псевдонимы `@` и `@testing`, прокси `/api`, Vitest
- `components.json` — псевдонимы shadcn/ui: компоненты в `src/shared/ui`, утилиты в `src/shared/lib`
- `tsconfig.json` — корневой конфиг: ссылки на два ниже
- `tsconfig.app.json` — типы приложения и тестов: `src` и `testing`
- `tsconfig.node.json` — типы оснастки: конфигурации сборки и сквозные тесты
- `eslint.config.js`, `.prettierrc.json`, `.prettierignore` — линт и формат
- `steiger.config.ts` — правила границ слоёв Feature-Sliced Design
- `playwright.config.ts` — сквозные тесты в светлой и тёмной теме; пишущие сценарии отдельным проектом после читающих
- `docker-compose.yml` — контур сборки и сквозных тестов: интерфейс и бэкенд из `../tracker`
- `docker-compose.prod.yml` — интерфейс рядом с прод-контуром бэкенда: адрес задаётся переменной
- `.nvmrc` — версия Node
- `.gitignore` — что не попадает в репозиторий
