# ui/e2e-demo

Материал для записи `docs/assets/demo-light.gif`/`demo-dark.gif` (TRK-82) — не
сквозные тесты. Свой `testDir` (`../playwright.demo.config.ts`) и свой изолированный
контур бэкенда: `pnpm e2e` (`playwright test` без `-c`) эту папку не подхватывает.

## Файлы
- `README.md` — как воспроизвести запись целиком: свой контур бэкенда со своим тегом
  образа и портами, участник `claude`, наполнение фона, запись (дважды, по теме),
  сведение в GIF `ffmpeg` в контейнере, гашение контура
- `demo-recording.spec.ts` — сценарий: доска уже наполнена фоном, агент заводит задачу
  REST-вызовом от лица `claude` (то же самое, что сделал бы вызов инструмента MCP —
  один сценарий `services` на оба интерфейса), двигает её по статусам, подшивает
  записи, переходит в карточку задачи
- `seed-background.py` — наполняет доску девятью фоновыми задачами (`APP-1`…`APP-9`:
  3 backlog, 2 open, 2 in_progress, 1 waiting, 1 done) до начала записи, так, чтобы
  колонки не пустовали под записью; только стандартная библиотека Python, без
  зависимостей
