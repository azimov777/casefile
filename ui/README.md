# tracker-ui

Интерфейс человека для трекера задач, которые ведут агенты. Человек здесь наблюдает
и отвечает на вопросы; задачи создают и двигают агенты через MCP бэкенда.

Бэкенд: репозиторий `tracker` рядом (`../tracker`), контракт в его `openapi.json`,
карта для фронтенда в его `docs/FRONTEND.md`.

Что и зачем строим: `docs/CONCEPT.md`. Как строим: `docs/CONVENTIONS.md`. Порядок
работ: `docs/ROADMAP.md`, задания в `docs/tasks/`.

## Требования

Node 22 или новее и pnpm — для разработки; Docker и Docker Compose — для сборки
и сквозных тестов. pnpm ставить отдельно не нужно, его версию задаёт `packageManager`:

```bash
corepack enable pnpm
pnpm install
```

## Разработка

Интерфейс ходит на свой источник и полагается на прокси `/api`, поэтому нужен
поднятый бэкенд. Проще всего — рабочий контур соседнего репозитория
(`../tracker/README.md`, «Быстрый старт»): миграции, `init` печатает первый токен,
`demo` наполняет очередь `DEMO`.

```bash
pnpm dev                                   # прокси /api на http://localhost:8000
VITE_API_URL=http://localhost:8080 pnpm dev  # или на любой другой бэкенд
```

Откройте адрес, который напечатал Vite, введите токен участника — и попадёте
на `/tasks`. Токен хранится только в `localStorage` и уходит на сервер заголовком
`Authorization`; в адресе страницы его нет никогда.

## Проверки

```bash
pnpm check   # формат, линт, типы, границы слоёв (steiger), модульные и страничные тесты
pnpm e2e     # Playwright против настоящего бэкенда в Docker
pnpm gen:api # перегенерировать клиент из ../tracker/openapi.json
```

`pnpm check` сверяет закоммиченный `src/shared/api/openapi.ts` с контрактом соседнего
репозитория и словарь ошибок с его `docs/ERRORS.md`: разошлись — прогон падает
и говорит, что делать.

`pnpm e2e` поднимает свой контур целиком (база, бэкенд, собранный образ интерфейса),
применяет миграции, наполняет демо-данными, выпускает токен и гасит всё за собой.
Первый прогон собирает образы и потому долгий.

## Сборка и контур

```bash
docker compose up -d --wait ui    # интерфейс на http://localhost:8080 и бэкенд рядом
docker compose run --rm migrate   # миграции
docker compose run --rm init      # владелец и его первый токен
docker compose run --rm demo      # демо-данные
docker compose down -v            # погасить вместе с данными
```

Наружу торчит только интерфейс: `/api` проксирует nginx внутрь сети compose. Порт
меняется переменной `UI_PORT`. Порты рабочего контура бэкенда (8000, 8100, 5432)
этот контур не занимает — их можно держать поднятыми одновременно.

## Папки

- `docs/` — концепция, соглашения, дорожная карта, задания для агентов, заметки
- `src/` — исходный код по слоям Feature-Sliced Design
- `testing/` — обвязка модульных и страничных тестов: подмена API, рендер приложения
- `e2e/` — сквозные сценарии Playwright и подъём контура для них
- `docker/` — образ интерфейса и конфигурация nginx
