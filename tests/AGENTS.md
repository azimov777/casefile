# tests

Тесты идут на реальной PostgreSQL из compose-контура: проект опирается на JSONB и специфичные
индексы, на SQLite они не воспроизводятся. Запуск — `docker compose run --rm test`.

Набор покрывает фундамент (участники, токены, очереди, автор), ядро задачи (переходы,
правки по статусам, версия), дело (записи агента, обязательная сводка, вердикты, вопросы,
пакет преемника) и связи: виды, циклы, блокировка входа в работу, дети при закрытии. Тесты
поиска и ленты пишутся вместе с ними (задачи 25–29).

## Файлы
- `conftest.py` — общие фикстуры: тестовая база с миграциями, сессия с откатом, клиенты, токены наборов, очередь, задача
- `test_api_contract.py` — сплошная проверка контракта: оболочка у всех маршрутов, справочник ошибок, полнота документации
- `test_auth.py` — аутентификация: наборы, метка временного агента, отозванный токен, отметка использования
- `test_case_api.py` — эндпоинты дела: обзорные проверки задачи 23 через HTTP, полный цикл до `done`
- `test_case_service.py` — сценарии дела: подшивка записей, проверки по базе, пакет преемника, вопросы
- `test_domain_case.py` — домен дела без базы: форма нагрузки по типам, ссылки, выведенные заголовки
- `test_domain_foundation.py` — домен без базы: имена, ключи очередей, метки, наборы, структура автора
- `test_domain_links.py` — домен связей без базы: пары видов, канонизация направления, имя стороны
- `test_domain_tasks.py` — домен задачи без базы: ключ, таблица переходов, шаг назад, проверки перехода, форма полей
- `test_entry_numbering.py` — гонка за номером записи: двадцать одновременных записей в одну задачу без дыр
- `test_errors.py` — единый формат ошибки: доменное исключение, ошибка схемы, несуществующий маршрут
- `test_health.py` — smoke-тест `/health` и проверка того, что фикстура доходит до настоящей БД
- `test_links_api.py` — эндпоинты связей: обзорные проверки задачи 24 через HTTP, отказы и записи в делах
- `test_links_service.py` — сценарии связей: две стороны одной строки, записи в обоих делах, циклы, `blocked`
- `test_mcp_server.py` — каркас MCP: пустой набор инструментов, `initialize`, токен и метка из заголовков
- `test_openapi.py` — пригодность схемы к генерации клиента: идентификаторы, модели ответов
- `test_participants_api.py` — эндпоинты участников: оболочка, доступ по набору, канонизация имени
- `test_participants_service.py` — сценарии участников: регистрация, конфликт имени, правка описания
- `test_queue_numbering.py` — гонка за номером задачи: пятьдесят одновременных выдач на своих сессиях
- `test_questions_api.py` — эндпоинт вопросов: открытость, адресат, признак `blocking`, фильтр по очереди
- `test_queues_api.py` — эндпоинты очередей: доступ по набору, неизменяемый ключ, частичное обновление
- `test_queues_service.py` — сценарии очередей: создание, правка, чтение, выдача номеров
- `test_response_envelope.py` — форма ответа: одиночный ресурс в `data`, коллекция с `meta`
- `test_setup.py` — первичная инициализация: пустая установка размыкается, работающая не трогается
- `test_tasks_api.py` — эндпоинты задач: обзорные проверки задачи 22 через HTTP, неизменяемость записей по схеме
- `test_tasks_service.py` — сценарии задач: создание, правки по статусам, переходы, версия, служебные записи
- `test_tokens_api.py` — эндпоинты токенов: секрет один раз, отзыв, общий агентский токен через HTTP
- `test_tokens_service.py` — сценарии токенов: выпуск именного и общего, список, идемпотентный отзыв
- `test_transactions.py` — граница транзакции: коммит, откат, падение самого коммита, конфликт целостности
