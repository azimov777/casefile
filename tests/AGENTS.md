# tests

Тесты бэкенда: идут в контейнере на настоящей PostgreSQL, весь набор — `docker compose run --rm test`.
Файл на механику: сценарии, REST и MCP одной механики рядом; гонки — на настоящих сессиях; отдельно —
сверка поставляемых файлов и контуров запуска с кодом.

## Папки
- `data/` — данные, которые неудобно держать в коде теста: вендорная схема `server.json` реестра MCP и архивы
  демо-данных выпусков, менявших схему базы

## Файлы
- `conftest.py` — общие фикстуры: тестовая база с миграциями, сессия с откатом, клиенты REST и MCP, вызов
  инструмента, проект с областью и без, помощники `make_area`, `make_task`, `move_task`
- `test_domain_*.py` — домен без базы: дело, фундамент (имена, ключи, метки), лента, связи, отбор, задача
- `test_*account*.py` — учётные записи: заведение, отказы, права администратора, отключение с отзывом токенов,
  администратор, которого установка заводит сама
- `test_password*.py` — пароль: хеш scrypt без базы и вход по почте и паролю с токеном сеанса
- `test_*token*.py` — токены: выпуск и отзыв через сценарии и REST, ключ интерфейса и токен агента от установки,
  свои токены людей
- `test_auth.py` — аутентификация: метка временного агента, отозванный и просроченный токен, отметка использования
- `test_*owner*.py` — хозяин агента (`agent_of`) и локальный вход OAuth от имени человека машины
- `test_setup.py` — первичная инициализация: пустая установка размыкается, работающая не трогается
- `test_participants_*.py` — участники: сценарии и REST
- `test_project*.py` — проекты: сценарии и REST, дело проекта, атрибуты, решения и знание с заменой, описание,
  архив, гонка за номером задачи
- `test_archive_visibility.py` — архивный проект скрыт по умолчанию из списков, поиска и входящей
- `test_area*.py` — области: карточка и атрибуты, знание в деле области, обязательная область новой задачи
- `test_task*.py` — задачи: сценарии и REST, поле `area`, перенос (одной и списком), момент `not_before`, блок `state`
- `test_assignee_takes_work.py` — вход в `in_progress` только исполнителю, через REST и MCP
- `test_check_edit.py` — правка одной проверки и пометка устаревшего вердикта
- `test_closing_warning.py` — исходы `partial` и `unverifiable` и предупреждение закрытия
- `test_case_*.py` — дело: сценарии и REST, факты в описи против `EntryType`
- `test_entry_numbering.py` — гонка за номером записи дела без дыр
- `test_drafts.py` — черновик знания в деле задачи и его подъём
- `test_remarks.py` — замечание человека и его разбор
- `test_questions_api.py` — вопросы поперёк задач: открытость, адресат, `blocking`, отбор по проекту
- `test_discussions.py` — обсуждения через сценарии и REST: адрес, привязка задач, ожидание, закрытие с итогом
- `test_links_*.py` — связи: сценарии и REST, обе стороны одной строки, циклы, `blocked`
- `test_search_*.py` — отбор задач: сценарий и REST, язык запросов и фильтр, признаки, курсор и страницы
- `test_journal_*.py` — лента: REST, поток SSE, ожидание на настоящих коммитах, уход клиента
- `test_wakeup.py` — слушатель `LISTEN/NOTIFY` журнала на настоящем соединении
- `test_field_changed_journal.py` — запись `field_changed` и её путь до потребителя ленты
- `test_last_entry_at.py` — признак `last_entry_at` против `updated_at`
- `test_idempotency*.py` — идемпотентность создающих вызовов через HTTP и гонка одновременных повторов
- `test_transactions.py` — граница транзакции: коммит, откат, падение коммита, конфликт целостности
- `test_integrity_conflicts.py` — гонка создающих вызовов: доменный отказ в MCP и командной строке
- `test_mutation_races.py` — гонка перехода со связью
- `test_end_to_end.py` — сквозные сценарии: цикл задачи через REST и через MCP с одинаковой описью
- `test_mcp_*.py` — MCP-сервер: каркас и `401`, инструменты через клиент SDK, метадата и `instructions`, раскладка
  файлов инструментов, stdio, вход OAuth, скил по SEP-2640, лента и обсуждения
- `test_bootstrap.py` — первый экран одним запросом
- `test_installation.py` — сведения установки: адрес MCP, один ответ любому токену
- `test_archive.py` — перенос установки: выгрузка и приём архива
- `test_release_archives.py` — архивы демо-данных прошлых выпусков из `data/` принимаются в head без потерь
- `test_migrations.py` — миграции, переносящие данные: откат и повтор
- `test_releases.py` — проверка последнего выпуска без настоящего GitHub
- `test_demo.py` — демо-данные: все статусы, типы записей, виды связей, повтор
- `test_health.py` — smoke-тест `/health` на настоящей БД
- `test_shutdown.py` — остановка процесса: поток ленты кончается по сигналу, начатая запись дописывается
- `test_errors.py` — единый формат ошибки
- `test_response_envelope.py` — оболочка ответа: ресурс в `data`, коллекция с `meta`
- `test_api_contract.py` — сплошная проверка контракта по `app/api/contract.py`
- `test_openapi.py` — пригодность схемы к генерации клиента
- `test_artifacts.py` — поставляемые артефакты: `openapi.json` против кода, `Settings` против `.env.example`
- `test_version.py` — версия продукта одна, из `pyproject.toml`, во всех артефактах
- `test_compose.py` — контуры запуска: одни переменные в дев и прод, тома, публикация портов
- `test_installers.py` — установщики `install.sh` и `install.ps1` текстом: шаги, согласие и копии, одинаковость
- `test_auto_update.py` — автообновление установки: канал `stable`, обновлятор против подставного `docker`
- `test_plugin_*.py` — манифесты плагинов и узкая ветка `plugin`
- `test_skill_*.py` — файлы скилов `skills/*/SKILL.md` по формату agentskills.io
- `test_mcpb_manifest.py` — расширение Claude Desktop `mcpb/`: версия, имя сервера, мост
- `test_server_json.py` — карточка `server.json` против вендорной схемы из `data/`
- `test_readme_tools.py` — README для каталогов MCP против зарегистрированных инструментов
- `test_agent_phrases_everywhere.py` — сплошная сверка фраз для агента во всех копиях
- `test_check_dco_script.py` — скрипт подписи вклада и исключение для Dependabot
- `test_merge_script.py` — скрипт слияния ветки задачи
- `test_watch_journal_sample.py` — образец сторожа `scripts/watch-journal.sh`
- `test_notes.py` — заметки `docs/notes/`: поля записи и указатели «Где:» в живой код
- `test_doc_links_in_code.py` — ссылки на документы в комментариях кода ведут на существующие файлы
