# tests

Тесты идут на реальной PostgreSQL из compose-контура: проект опирается на JSONB и специфичные
индексы, на SQLite они не воспроизводятся. Запуск — `docker compose run --rm test`.

Набор покрывает фундамент (участники, токены, очереди, автор), ядро задачи (переходы,
правки по статусам, версия), дело (записи агента, обязательная сводка, вердикты, вопросы,
пакет преемника), связи (виды, циклы, блокировка входа в работу, дети при закрытии, родословная закрытой задачи), замечания человека и их разбор, отбор
задач (язык запросов, структурный фильтр, вычисляемые признаки, курсор), ленту журнала
(хвост по `seq`, долгое ожидание на оповещениях, гонка ста параллельных подшивок, поток SSE
с продолжением), идемпотентность создающих вызовов (повтор, конфликт отпечатков, срок
жизни ключа, гонка одновременных повторов) и MCP: каждый инструмент через настоящий клиент
SDK, состав `tools/list` по наборам токена, промпт и инструкции из скила. Отдельно —
выдача доступа: первый токен человеку и ключ набора `main`, который установка кладёт в
файл своему интерфейсу. Отдельным слоем —
надёжность на двух транзакциях: гонка перехода со связью, гонка создающих вызовов в MCP и
командной строке, прекращение долгого опроса ленты после ухода клиента. Сверху лежат
сквозные сценарии: полный цикл задачи через REST и тот же цикл через MCP, дающие одну и ту
же опись дела, и сценарий ожидания ответа на блокирующий вопрос. Отдельно от кода
лежат проверки поставляемых артефактов и самих контуров запуска: закоммиченная схема
против кода, `.env.example` против `Settings`, одинаковое окружение приложения в
дев- и прод-контуре, скрипт, которым ветка задачи уходит в `main`, и скрипт проверки
подписи вклада — включая узкое исключение для Dependabot.

## Файлы
- `conftest.py` — общие фикстуры и помощники: тестовая база с миграциями, сессия с откатом, клиенты REST и MCP, вызов инструмента, токены наборов, очередь, задача
- `test_accounts.py` — учётные записи: заведение с паролем один раз, отказы с причиной, право администратора и его отсутствие у агента и набора `task`, отключение с отзывом токенов, последний администратор, почта, сброс и смена пароля, двое в одной команде, команды `account-*`
- `test_admin_account.py` — администратор, которого установка заводит сама: при подъёме, `init` и шаге агента, у владельца до учётных записей, перенос прежнего `TRACKER_PASSWORD_HASH` без перетирания и отказ испорченному
- `test_agent_token.py` — токен агента от установки: набор `main` участнику `agent` в файле с правами `0600`, независимость от порядка с `local-token`, неизменность при повторе, новый токен и отзыв старого при потере файла, ключ интерфейса не трогается при переиздании
- `test_api_contract.py` — сплошная проверка контракта: оболочка у всех маршрутов, токен у всех, кроме объявленных в `TOKEN_EXEMPT`, справочник ошибок, полнота документации
- `test_artifacts.py` — поставляемые артефакты: закоммиченный `openapi.json` против кода, коды в отказах MCP, поля `Settings` против `.env.example`
- `test_auth.py` — аутентификация: наборы, метка временного агента, отозванный и просроченный токен, отметка использования
- `test_bootstrap.py` — первый экран: участник, его учётная запись, токен запроса с набором и идентификатором из списка токенов (именные `task` и `main`, общий агентский), очереди, счётчик вопросов
- `test_case_api.py` — эндпоинты дела: обзорные проверки задачи 23 через HTTP, полный цикл до `done`
- `test_case_index_facts.py` — факты в описи: сплошная сверка форм с `EntryType` в обоих

  от длины разделов, цена пакета в запросах
- `test_case_service.py` — сценарии дела: подшивка записей, проверки по базе, пакет преемника, вопросы
- `test_compose.py` — контуры запуска: один и тот же набор переменных у приложения в дев- и прод-контуре, объявленное чтение `.env`, ключ интерфейса в каталоге, видимом хосту, владелец записанного файла, названный контуром, публичный адрес MCP в общем окружении контура, запрет монтировать что-либо внутрь каталога, приехавшего с хоста, один адрес публикации `CASEFILE_BIND` у обоих портов и режим пароля интерфейса из той же подстановки, что у API, `X-Real-IP` — только от службы `ui`, которая его перезаписывает
