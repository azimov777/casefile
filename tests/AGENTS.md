# tests

Тесты идут на реальной PostgreSQL из compose-контура: проект опирается на JSONB и специфичные
индексы, на SQLite они не воспроизводятся. Запуск — `docker compose run --rm test`.

Набор покрывает фундамент (участники, токены, очереди, автор), ядро задачи (переходы,
правки по статусам, версия), дело (записи агента, обязательная сводка, вердикты, вопросы,
пакет преемника), связи (виды, циклы, блокировка входа в работу, дети при закрытии), отбор
задач (язык запросов, структурный фильтр, вычисляемые признаки, курсор), ленту журнала
(хвост по `seq`, долгое ожидание на оповещениях, гонка ста параллельных подшивок, поток SSE
с продолжением), идемпотентность создающих вызовов (повтор, конфликт отпечатков, срок
жизни ключа, гонка одновременных повторов) и MCP: каждый инструмент через настоящий клиент
SDK, состав `tools/list` по наборам токена, промпт и инструкции из скила. Отдельным слоем —
надёжность на двух транзакциях: гонка перехода со связью, гонка создающих вызовов в MCP и
командной строке, прекращение долгого опроса ленты после ухода клиента. Сверху лежат
сквозные сценарии: полный цикл задачи через REST и тот же цикл через MCP, дающие одну и ту
же опись дела, и сценарий ожидания ответа на блокирующий вопрос. Отдельно от кода
лежат проверки поставляемых артефактов и самих контуров запуска: закоммиченная схема
против кода, `.env.example` против `Settings`, одинаковое окружение приложения в
дев- и прод-контуре.

## Файлы
- `conftest.py` — общие фикстуры и помощники: тестовая база с миграциями, сессия с откатом, клиенты REST и MCP, вызов инструмента, токены наборов, очередь, задача
- `test_api_contract.py` — сплошная проверка контракта: оболочка у всех маршрутов, справочник ошибок, полнота документации
- `test_artifacts.py` — поставляемые артефакты: закоммиченный `openapi.json` против кода, пути и коды ошибок из `FRONTEND.md`, коды в отказах MCP, поля `Settings` против `.env.example`
- `test_auth.py` — аутентификация: наборы, метка временного агента, отозванный токен, отметка использования
- `test_bootstrap.py` — первый экран: участник, очереди, счётчик вопросов; общий агентский токен без участника
- `test_case_api.py` — эндпоинты дела: обзорные проверки задачи 23 через HTTP, полный цикл до `done`
- `test_case_service.py` — сценарии дела: подшивка записей, проверки по базе, пакет преемника, вопросы
- `test_compose.py` — контуры запуска: один и тот же набор переменных у приложения в дев- и прод-контуре, объявленное чтение `.env`
- `test_demo.py` — демо-данные: все статусы, все типы записей, все виды связей, метка временного агента, идемпотентность повтора
- `test_domain_case.py` — домен дела без базы: форма нагрузки по типам, ссылки, выведенные заголовки
- `test_domain_foundation.py` — домен без базы: имена, ключи очередей, метки, наборы, структура автора
- `test_domain_journal.py` — домен ленты без базы: потолок ожидания, разбор `Last-Event-ID`, слияние двух позиций
- `test_domain_links.py` — домен связей без базы: пары видов, канонизация направления, имя стороны
- `test_domain_search.py` — домен отбора без базы: грамматика языка, позиция ошибки, потолки, склейка фильтров
- `test_domain_tasks.py` — домен задачи без базы: ключ, таблица переходов, шаг назад, проверки перехода, форма полей
- `test_end_to_end.py` — сквозные сценарии: цикл задачи через REST и через MCP с одинаковой описью, ожидание ответа на блокирующий вопрос
- `test_entry_numbering.py` — гонка за номером записи: двадцать одновременных записей в одну задачу без дыр
- `test_errors.py` — единый формат ошибки: доменное исключение, ошибка схемы, несуществующий маршрут
- `test_health.py` — smoke-тест `/health` и проверка того, что фикстура доходит до настоящей БД
- `test_integrity_conflicts.py` — гонка создающих вызовов: проигравший получает доменный отказ в MCP и в командной строке, а не ошибку драйвера
- `test_idempotency.py` — идемпотентность через HTTP: повтор, конфликт отпечатков, срок жизни, все создающие маршруты
- `test_idempotency_race.py` — одновременные повторы одного ключа на настоящих сессиях: одна задача, откат освобождает ключ
- `test_journal_api.py` — лента через HTTP: хвост по номеру, фильтры, страницы и курсор, потолок ожидания
- `test_journal_disconnect.py` — ушедший клиент прекращает долгий опрос ленты; отключение изображается каналом ASGI
- `test_journal_stream.py` — поток SSE: форма кадра, продолжение по `Last-Event-ID`, потолок соединений; кадры читаются прямо из ASGI
- `test_journal_wait.py` — ожидание на настоящих коммитах: пробуждение оповещением, сигнал не раньше строки, сто параллельных подшивок
- `test_links_api.py` — эндпоинты связей: обзорные проверки задачи 24 через HTTP, отказы и записи в делах
- `test_links_service.py` — сценарии связей: две стороны одной строки, записи в обоих делах, циклы, `blocked`
- `test_mcp_journal.py` — ожидание ленты из MCP: пустой ответ по таймауту и пробуждение оповещением из чужого процесса
- `test_mcp_server.py` — каркас MCP: `initialize`, разбор токена и метки из заголовков, проверка здоровья
- `test_mcp_skill.py` — скил наружу: промпт целиком, `instructions` из раздела «Кратко», совпадение имён инструментов
- `test_mcp_tools.py` — инструменты через клиент SDK: состав по наборам, пакет преемника против REST, дело, связи, реестры
- `test_migrations.py` — миграции на данных: задача из `review` переезжает в `in_progress` записью от трекера, откат и повтор
- `test_mutation_races.py` — гонка перехода со связью: закрытого родителя с открытым ребёнком и работы поверх блокера не бывает
- `test_notes.py` — формат заметок `docs/notes/`: у каждой записи все четыре поля и их порядок
- `test_openapi.py` — пригодность схемы к генерации клиента: идентификаторы, модели ответов
- `test_participants_api.py` — эндпоинты участников: оболочка, доступ по набору, канонизация имени
- `test_participants_service.py` — сценарии участников: регистрация, конфликт имени, правка описания
- `test_queue_numbering.py` — гонка за номером задачи: пятьдесят одновременных выдач на своих сессиях
- `test_questions_api.py` — эндпоинт вопросов: открытость, адресат, признак `blocking`, фильтр по очереди
- `test_queues_api.py` — эндпоинты очередей: доступ по набору, неизменяемый ключ, частичное обновление
- `test_queues_service.py` — сценарии очередей: создание, правка, чтение, выдача номеров
- `test_response_envelope.py` — форма ответа: одиночный ресурс в `data`, коллекция с `meta`
- `test_search_api.py` — эндпоинт списка задач: обзорные проверки задачи 25 через HTTP, выбор полей, отказы с позицией
- `test_search_service.py` — сценарий отбора: два входа с одним результатом, признаки против карточки, курсор при вставке
- `test_setup.py` — первичная инициализация: пустая установка размыкается, работающая не трогается
- `test_tasks_api.py` — эндпоинты задач: обзорные проверки задачи 22 через HTTP, неизменяемость записей по схеме
- `test_tasks_service.py` — сценарии задач: создание, правки по статусам, переходы, версия, служебные записи
- `test_tokens_api.py` — эндпоинты токенов: секрет один раз, отзыв, общий агентский токен через HTTP
- `test_tokens_service.py` — сценарии токенов: выпуск именного и общего, список, идемпотентный отзыв
- `test_transactions.py` — граница транзакции: коммит, откат, падение самого коммита, конфликт целостности
