# scripts

Команды, которым нужен хост: git и docker живут снаружи контейнера, и обёртка над ними
тоже. Прогон, который такая команда запускает, идёт в контейнере — установка Python на
хост по-прежнему не поддерживается (`docs/CONVENTIONS.md`, раздел «Запуск: всё работает
в Docker»); исключение — `pnpm check`, которым `merge-task-branch.sh` проверяет ветки,
трогающие `ui/`: он, как и в `ui/scripts/`, идёт на хосте. `watch-journal.sh` — другой
случай той же идеи «нужен хост»: он ходит по сети на опубликованный порт установки
голым `curl` и внутрь контейнера не идёт вовсе.

## Файлы
- `build-openai-plugin.sh` — ZIP плагина `casefile` (только скил) для загрузки на platform.openai.com/plugins: `.codex-plugin/` (манифест без `mcpServers`, без mcp.json), `skills/` без своей карты и `LICENSE`, имя `casefile-<версия>.zip`; падает, если версия манифеста не равна версии выпуска или иконка больше 5 МиБ; ничего не подаёт (TRK-461)
- `build-plugin-branch.sh` — дерево узкой ветки `plugin`: `.claude-plugin/`, `.codex-plugin/`, `.cursor-plugin/`, `gemini-extension.json`, `skills/` без своей карты, `LICENSE`, `README.md`; падает при 512 файлах и больше, файле не-картинки больше 256 КиБ или версии любого манифеста (Claude Code, Codex, Cursor, Gemini) не равной версии выпуска; с `--commit ТЕГ [--parent REF]` строит коммит выпуска (без коммита, если дерево родителя то же); ту же сборку зовёт джоб `channel` конвейера выпуска (TRK-478)
- `check-auto-update.sh` — живая проверка автообновления установки на своём `registry:2`: переход установки с `latest` на канал `stable` и замена обновлятора, новый выпуск без перезапуска Docker, проверка без выпуска, коммит main без тега, закрепление и выключатель, повторный установщик, откат выпуска, который не поднялся, и следующий выпуск после него; всё своё гасит на выходе
- `check-dco.sh` — подпись вклада: каждый коммит диапазона несёт `Signed-off-by` своего автора, кроме коммитов Dependabot в PR, которые GitHub сам числит за ним; тем же файлом проверяет конвейер и человек до отправки PR
- `check-skill-install.sh` — живая проверка шага «скил» и плагина установщика (TRK-408, TRK-452) на своём http-git стенде в изолированных `HOME`/`CLAUDE_CONFIG_DIR`/`CODEX_HOME`: `CASEFILE_SKILL_ONLY=1 CASEFILE_URL=…` ставит плагин с адресом в Claude Code и Codex (`mcp list` показывает адрес), скил в `npx skills` и заглушку Hermes, без адреса плагин встаёт с адресом по умолчанию без входа, ручные записи `casefile` убираются, а чужие остаются, токена в конфигах нет, каталоги харнессов без файлов корня репозитория (ветка `plugin`), перевод установки со `stable` на `plugin` (TRK-494), идемпотентность и сдвинутые ветки `stable` и `plugin` с новой версией, PATH без `docker` и без всех харнессов, `CASEFILE_SKILL=0` при полной установке, ответ «N» без единого изменения чужих файлов и копии `.casefile-bak` перед правкой (TRK-546); отпечаток настоящих `~/.claude`, `~/.codex`, `~/.agents` до и после
- `merge-task-branch.sh` — слияние ветки задачи: слить без коммита, прогнать на результате линтер бэкенда и набор всегда, `pnpm check` в `ui/` — если ветка трогает `ui/`, закоммитить только зелёное во всём со строкой `Merge-verified:`; перед своим слиянием называет слияния без этой строки
- `watch-journal.sh` — ВРЕМЕННЫЙ образец сторожа журнала для `docs/agent-install.md`
  («Learn about news in your tasks»), не поддерживаемый инструмент: не входит ни в один
  `docker-compose*.yml`, ничего не пишет в трекер и не знает, жив ли агент; долгий опрос
  `GET /api/v1/journal` по отслеживаемым задачам, продолжение по `seq`, переживает отказ
  установки
