# app/api/routes

Роутеры по предметным областям: один файл — одна область, каждый подключается к `api_router`
из `app/api/router.py`. Исключение — `health.py`: он висит вне версионированного префикса.

Второе исключение — поток ленты в `journal.py`: единственный маршрут `/api/v1`, чей ответ
не завёрнут в `data`. Причина объявлена кодом в `app/api/contract.py` (`ENVELOPE_EXEMPT`)
и заводится вместе с маршрутом, иначе падает одна из двух проверок контракта.

Третье — `session.py`: вход владельца по паролю подключается к `session_router`, а не к
`api_router`, потому что токена не требует. Такие маршруты тоже объявлены кодом
(`TOKEN_EXEMPT` в `app/api/contract.py`).

## Файлы
- `__init__.py` — маркер пакета
- `bootstrap.py` — первый экран интерфейса одним запросом: участник, его токен с набором, очереди, число вопросов к нему
- `installation.py` — сведения установки, одинаковые для любого токена: публичный адрес MCP
- `health.py` — проверка здоровья `/health`: подтверждает живое соединение с БД для мониторинга
- `journal.py` — лента журнала: хвост по `seq` с ожиданием и тот же хвост потоком SSE
- `links.py` — связи между задачами: поставить и снять; чтения нет, связи приезжают в карточке
- `participants.py` — реестр участников: список, регистрация, чтение, правка описания
- `queues.py` — реестр очередей: список, создание, чтение, правка названия и описания
- `questions.py` — вопросы поперёк задач: «входящая» участника, представление над делом
- `remarks.py` — замечания поперёк задач: что ещё не разобрали, представление над делом
- `session.py` — вход владельца по паролю: сеанс браузера в куке `HttpOnly`, проверка сеанса для nginx, выход
- `tasks.py` — задачи: список с языком запросов и структурным фильтром, создание, пакет преемника, обновление, переход, закрытие, записи дела
- `tokens.py` — токены доступа: список, выпуск с секретом в ответе, отзыв
