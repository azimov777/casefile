# app/db/migrations/versions

Версии схемы. Имя файла начинается с даты и времени создания в UTC (пояс закреплён в
`alembic.ini`, чтобы имя не зависело от машины), порядок применения задаётся полем
`down_revision` внутри файла, а не именем. Правка применённой ревизии запрещена — нужна новая;
переименование файла ревизией не считается, идентификатор лежит внутри.

Ревизия может нести и данные: строки, без которых система не работает на свежей базе, создаются
здесь, а не командой инициализации. Такие значения дублируют константу в коде литералом —
миграция не должна зависеть от кода приложения, который со временем меняется.

Цепочка начата заново задачей 20: старые ревизии удалены вместе со старым доменом.
Прежняя схема целиком живёт в git по коммиту `49e2e49`.

## Файлы
- `20260903_1200_actors_and_api_tokens.py` — начало цепочки: акторы, токены доступа и системный актор
- `20260903_2100_participants_tokens_and_queues.py` — фундамент: участники, токены с наборами, очереди; акторы удалены
- `20260903_2300_tasks_and_entries.py` — задачи и записи дела; триггер, запрещающий правку и удаление записей
- `20260903_2340_case_entry_lookups.py` — индексы под выдачу вопросов: по типу и `seq`, частичный GIN по нагрузке вопросов
- `20260904_0100_task_links.py` — связи задач: одна строка на связь, канонические виды под CHECK, индексы с обеих сторон
- `20260904_0300_search_indexes.py` — индексы отбора: порядок по номеру задачи, время обновления, триграммы названия и описания
- `20260904_0500_idempotency_keys.py` — ключи идемпотентности: пара «токен и ключ» под уникальностью, ответ в JSONB, индекс под попутную уборку
- `20260905_1700_drop_review_status.py` — снятие статуса `review`: задачи переводятся в `in_progress` записью `status_changed` от трекера, ограничение CHECK заменяется
- `20260906_1700_field_changed_entry.py` — тип записи `field_changed`: правка обвязки задачи оставляет след в деле
- `20260906_2000_remark_and_resolution.py` — типы записей `remark` и `resolution`: замечание человека и его разбор с исходом
- `20260907_2230_waiting_status.py` — статус `waiting`: ограничение CHECK расширяется, строки не трогаются — статус ставится только явным переходом
- `20260908_1030_drop_task_tags.py` — снятие меток задачи: колонка `tags` и GIN-индекс сносятся, значения теряются сознательно
- `20260922_1900_accounts.py` — учётные записи людей и срок у токена сеанса; строк не заводит, администратора заводит шаг подъёма
