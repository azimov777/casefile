# app/services

Сценарии приложения: оркестрация домена, работа с репозиториями, запись в журнал изменений
и outbox. Один сценарий — одна функция, вызываемая и из REST, и из MCP, и из командной строки;
дублировать логику в интерфейсах нельзя.

Транзакцию сценарии не фиксируют: границу держит вход в приложение (`get_session` для запроса,
`session_scope` для воркера и команды). `flush` внутри сценария допустим и нужен.

## Файлы
- `__init__.py` — маркер пакета
- `actors.py` — акторы и токены: создать, изменить, выпустить токен, отозвать, перечислить
- `auth.py` — аутентификация по секрету токена; общая для REST, MCP и командной строки
- `catalogs.py` — справочники: создание, области действия, защита от удаления и смены категории
- `fields.py` — реестр полей: описание, применимость к паре «очередь + тип», проверка значений
- `issue_usage.py` — сколько задач ссылается на справочник или поле; одна точка на весь проект
- `issues.py` — задачи: создание, чтение, **единая точка применения изменений**, версии, наблюдатели
- `permissions.py` — единая точка проверки прав: в v1 разрешает всё, но вызывается везде
- `queues.py` — очереди: конфигурация целиком, значения по умолчанию, архивация, нумерация,
  разрешение ссылок `TRK.open` и `TRK.severity`
- `workflow.py` — проверка допустимости смены статуса; заглушка-маркер до задачи 07
