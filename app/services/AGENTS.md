# app/services

Сценарии приложения: оркестрация домена, работа с репозиториями, служебные записи дела.
Один сценарий — одна функция, вызываемая и из REST, и из MCP, и из командной строки;
дублировать логику в интерфейсах нельзя.

Транзакцию сценарии не фиксируют: границу держит вход в приложение (`get_session` для
запроса, `session_scope` для MCP-сервера и команды). `flush` внутри сценария допустим и нужен.

Здесь фундамент, ядро задачи, дело, связи между задачами, отбор задач, лента журнала,
идемпотентность создающих вызовов, первый экран и демо-данные — один механизм на REST
и на MCP.
Ожидание ленты — единственный сценарий, который коммитит сам: он висит десятки секунд и
обязан отпустить соединение из пула на время сна.

## Файлы
- `__init__.py` — маркер пакета
- `accounts.py` — учётные записи: право администратора, заведение, изменение и отключение с отзывом токенов, сброс и смена пароля с отзывом сеансов, правка своего состояния знакомства без записи в дело
- `archive.py` — перенос установки: выгрузка архива администратору и приём в пустую установку с доводкой схемы до head; сеансы и ключи идемпотентности не едут, ключи машины приёмника переживают приём
- `areas.py` — области: завести по адресу `ПРОЕКТ/ключ` с записью `created`, прочитать, перечислить, править карточку, архивировать и восстановить с причиной; проект или область по ключу или адресу (`get_owner`)
- `attributes.py` — атрибуты проекта и области: задать значение одним действием (заведение или изменение с причиной, тот же текст — без записи), снятие с причиной, чтение; записи — в деле владельца
- `auth.py` — аутентификация по секрету токена и метке, отказ отозванному и просроченному; отдаёт структуру автора; проверка годности токена без подписи (`verify_token`) — для проверяющего службы mcp
- `bootstrap.py` — первый экран одним вызовом: участник за токеном, его учётная запись, токен, проекты, число открытых вопросов к нему
- `case.py` — дело задачи, проекта и области: записи агента и служебные, чтение с фильтрами, опись, признаки, вопросы поперёк задач
- `client_documents.py` — скачивание документа CIMD: своё разрешение имени с отказом внутренним адресам, соединение на проверенный адрес, без перенаправлений, предел размера и времени, только JSON, предел частоты и отрицательный кэш отказов; сеть подменяема
- `decisions.py` — записи знания проекта, решения и заметки: статус и преемник при чтении — у решений проекта, у записей дела проекта, у решений, на которые ссылается задача, и число ссылающихся задач; действующие решения и заметки ссылкой и заголовком для чтения проекта; проверки новой ссылки задачи и замены (`decision_not_in_force`, `finding_not_in_force`)
- `demo.py` — демонстрационные данные настоящими сценариями: проект `DEMO`, все статусы, все типы записей, три вида связей
- `freeze.py` — заморозка архивного проекта и области: единственное место отказов архива (проект называется первым), проверка в подшивке записи и первым шагом сценария, исключения — сами действия архива и снятие связи
- `idempotency.py` — выполнить один раз на ключ: занять пару «токен и ключ», сделать работу, сохранить ответ для повтора
- `installation.py` — сведения установки, одинаковые для любого токена: публичный адрес MCP из настроек
- `journal.py` — лента журнала: хвост по `seq` с фильтрами, долгое ожидание на оповещениях, поток и счётчик его соединений
- `links.py` — связи: поставить и снять с записью в делах обеих задач, проверка циклов, признак `blocked`
- `login.py` — вход по почте и паролю: токен сеанса со сроком, чтение и выход по куке, окна неудачных попыток на адрес, почту и установку в памяти процесса API
- `oauth.py` — вход через OAuth: публичный клиент DCR, клиент по документу CIMD с кэшем в строке клиента, согласие по политике «кому выдать» (локально — сразу, участник по клиенту, только на петле; в сети — вошедший человек и выбранный им агент, выбор участника для страницы), одноразовый код, обмен на токен участника и refresh, ротация refresh, отзыв цепочки при повторе
- `participants.py` — участники: зарегистрировать, изменить описание, прочитать, перечислить, найти или завести агента человека (`agent_of`, имя `<клиент>_<человек>`)
- `projects.py` — проекты: создать и изменить со служебной записью в деле проекта, прочитать, перечислить, выдать номер задачи
- `releases.py` — последний выпуск Casefile с GitHub: кэш на процесс API (удача — час, сбой — короче), только `production` и не выключенная `TRACKER_RELEASE_CHECK`; сбой — «обновления нет»
- `search.py` — отбор задач: склейка строки запроса со структурным фильтром, разрешение имён и значений, страница
- `setup.py` — первичная настройка: владелец и его первый токен на пустой установке; ключ для интерфейса локальной установки; учётная запись администратора с переносом прежнего пароля установки; токен агента этой машины
- `tasks.py` — задачи: создать, пакет преемника, единая точка мутаций с версией, переход по таблице с фактами из дела, закрытие одной транзакцией, перенос в другой проект с записью `moved`, одной задачи и списком с итогом по каждой
- `tokens.py` — токены: выпустить (с участником или общий агентский), перечислить, отозвать
