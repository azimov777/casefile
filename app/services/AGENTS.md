# app/services

Сценарии приложения: оркестрация домена, работа с репозиториями, служебные записи дела.
Один сценарий — одна функция, вызываемая и из REST, и из MCP, и из командной строки;
дублировать логику в интерфейсах нельзя.

Транзакцию сценарии не фиксируют: границу держит вход в приложение (`get_session` для
запроса, `session_scope` для MCP-сервера и команды). `flush` внутри сценария допустим и нужен.

Сценариев сейчас три: остальные снесены задачей 20 вместе со своим доменом.

## Файлы
- `__init__.py` — маркер пакета
- `actors.py` — акторы и токены: создать, изменить, выпустить токен, отозвать, перечислить
- `auth.py` — аутентификация по секрету токена; общая для REST, MCP и командной строки
- `permissions.py` — единая точка проверки прав: в v1 разрешает всё, но вызывается везде
