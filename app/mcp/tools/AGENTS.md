# app/mcp/tools

Инструменты MCP: тонкий слой над сценариями. Каждый разбирает аргументы, зовёт сценарий из
`services` и превращает результат в данные (`app/mcp/views.py`); своей логики здесь нет.

Общее для всех: один инструмент — один вид действия, результат — только данные без
подсказок, ошибка — код и причина, транзакцию держит `Runtime.call`. Докстрока инструмента
это его описание в `tools/list` и потому контракт вызова: что делает, что меняется снаружи,
что вернёт, когда откажет. Ходы агента живут в скиле (`CONCEPT.md`, 5.2). Создающий инструмент
принимает `idempotency_key`, и наличие этого аргумента проверяется при сборке
(`app/mcp/toolset.py`). Модуль подключается к серверу строкой в `__init__.py`.

## Файлы
- `__init__.py` — сборка: список модулей регистрации и общие границы инструментов
- `tasks.py` — задачи: пакет преемника, отбор, создание с родителем, частичная правка, переход
- `case.py` — дело: чтение записей, сводка, запись без нагрузки, вопрос, ответ, вердикт
- `links.py` — связи: поставить и снять; вид называет роль задачи из `key`
- `registry.py` — реестры: чтение очереди и участников набором `task`, запись — набором `main`
- `journal.py` — лента: хвост журнала с долгим ожиданием на оповещениях
