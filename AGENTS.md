# tracker

Бэкенд трекера задач для агентов: REST API для интерфейса человека (отдельный проект)
и MCP-сервер для агентов. Агенты ведут задачи и «дело» по каждой; человек смотрит и отвечает.

**Перед любой работой в репозитории:** прочитать `docs/CONCEPT.md` (что строим),
`docs/CONVENTIONS.md` (как строим — стек, слои, коммиты и обязательный протокол выполнения
задачи) и заметки в `docs/notes/` по своей области. Задания приходят задачами трекера.

**Очередь этого репозитория в трекере: `TRK`.** Задачи по бэкенду ведутся там; ключ
задачи `TRK-N` называет этот репозиторий, `UI-N` — репозиторий интерфейса `tracker-ui`.

## Папки
- `app/` — код приложения: слои api, mcp, domain, services, db, core
- `docs/` — концепция, соглашения, справочник ошибок, накопленные заметки
- `skill/` — скил дисциплины работы с трекером, который сервер раздаёт агентам через MCP
- `docker/` — образы для разработки и продакшена
- `tests/` — тесты, запускаются только в контейнере

## Файлы
- `README.md` — запуск проекта в Docker: контуры, миграции, демо-данные, MCP, тесты, переменные окружения
- `openapi.json` — выгруженная схема API, поставляемый артефакт; собирается `docker compose run --rm schema`
- `.env.example` — все переменные окружения с комментариями; копируется в `.env`
- `.gitignore`, `.dockerignore` — что не попадает в репозиторий и в образ
- `docker-compose.yml` — контур разработки, используется по умолчанию
- `docker-compose.prod.yml` — продакшен-контур
- `alembic.ini` — настройка миграций, путь к ревизиям и адрес БД
- `pyproject.toml` — зависимости, настройки ruff и pytest
