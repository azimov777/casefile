# Casefile v0.7.0

The release that takes the training project back out. v0.6.0 seeded a `START` project with
a task written for your agent; that mechanic is gone, and the "Start" screen, the on-screen
explanations and two phrases for the agent are what guide a new person now. The release also
makes automatic updates cleaner (no leftover containers, no half-finished switch of the
updater) and fixes a 502 on the board after only the API was recreated. It is breaking for
agents and installations in a few small ways, listed below, hence a minor version.

## Install

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/azimov777/casefile/main/install.sh | sh
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/azimov777/casefile/main/install.ps1 | iex
```

All you need is Docker. The board opens at `http://localhost:8080`, and the installer
prints the one command that connects your agent, followed by two short phrases to say to it.
An installation on v0.6.0 updates itself to this release within about an hour, or at the
next Docker start.

## What's new

- **No training project.** A fresh installation starts with no projects at all, as before
  v0.6.0. Nothing creates `START` or the task `START-1`, and the `tutorial` command and the
  `tutorial` service are removed. A `START` that an installation already has stays an
  ordinary project: it is not touched, archived or deleted, and you can keep working in it
  or archive it yourself.
- **Two phrases for the agent instead of three.** The "introduction" phrase that sent the
  agent to `START-1` is gone from the installers' output, `README.md`,
  `docs/agent-install.md`, the "Start" screen and the "Connect an agent" screen. What stays
  is unchanged: one phrase to create tasks and one to carry them out. The screens and
  documents say "two phrases" now.
- **"Skip" on the "Start" screen skips the whole introduction.** It now also hides all
  on-screen explanations, on the server, so it holds in every browser under the same
  account. "Show explanations again" on "Start" brings them back in one action. Finishing
  the introduction ("I get it") does not hide them; only "Skip" does. The walk-through
  still shows the explanations even while they are hidden.
- **The board explanation is accurate.** Its first sentence now says the board shows the
  tasks of one project or of all, depending on what is selected (it used to say "one
  project" even when no project was selected).
- **The board survives recreating only the API.** The interface's web server used to keep
  the address of the old `api` container, so after `docker compose up -d --force-recreate api`
  (for example after editing a backend-only setting in `.env`) every request through the
  board answered `502` until `ui` was restarted. It now looks the name up on each request.
  Setting `TRACKER_DNS_RESOLVER` is only needed if your Docker setup does not use the
  standard internal DNS.
- **Automatic updates leave no leftovers.**
  - When an update moves to a release that no longer has some service, the container of
    that service is removed, so `docker compose ps -a` is clean and compose does not warn
    about orphan containers.
  - The step that replaces the updater now waits for the previous updater to finish its
    whole check, including waiting for the services to become healthy. Before, it could
    replace the updater in the middle of that wait, so the switch was neither finished nor
    rolled back and the `previous` image tags stayed behind.
  - On start the updater removes `previous` tags left over from an interrupted earlier
    update.
  - A check with no new release still recreates nothing.

## Breaking for agents

- **The training task and the introduction phrase are gone.** There is no `START-1`, no
  task written for the agent, and no third phrase to say. An agent that was told to "take
  the tutorial task `START-1`" finds nothing at that key on a new installation. Say the
  two remaining phrases instead: create tasks, and carry them out.
- **The key `START` is an ordinary project key again.** `create_project` with the key
  `START` works like any other key. The error code `project_key_reserved` no longer exists,
  and neither does `tutorial_admin_missing`; a client that handled either code by name can
  drop that branch. `docs/ERRORS.md` and `openapi.json` no longer list them.
- MCP `instructions` and the tool contracts are otherwise unchanged; `create_project` only
  lost a sentence about `START` in its description.

## Upgrade notes

**What happens to your installation**

- **No database migration.** Your data, including any `START` project and its tasks, is
  left as it is. The introduction state of your account (`pending`, `completed`,
  `skipped`, hidden explanations) is unchanged.
- **The `tutorial` container is removed by itself.** It was a one-off service of v0.6.0
  and stays in Docker as a stopped container; the update removes it. Nothing to do.
- **The updater container is replaced once.** `docker-compose.prod.yml` changed the
  `updater` service (the `tutorial` step left its list of one-off steps), so its revision
  label moved, and `updater-renew` recreates the updater on the first start on this
  release, then removes leftover containers and stale `previous` tags. It is the normal
  path; do not be surprised to see the container restart.
- **`CASEFILE_LANGUAGE` and `TRACKER_*` lines in `.env` are ignored.** `CASEFILE_LANGUAGE`,
  `TRACKER_TUTORIAL_LANGUAGE` and `TRACKER_UI_PUBLIC_URL` no longer exist. If your `.env`
  from v0.6.0 has them, the application does not fail on them; you may delete the lines.
  The installers no longer choose a language or write that line.
- **Moving an installation.** An archive is again accepted only by an installation with no
  projects at all, as before v0.6.0; the exception for the training project is gone.
  An archive taken on v0.6.0 that contains `START` is accepted like any other: `START`
  arrives as an ordinary project.
- **API.** `openapi.json` and `docs/ERRORS.md` lose the two error codes above. Nothing else
  in the contract changes.

## Not verified yet

- **Nothing here was looked at in Safari.** Text and behaviour were checked in headless
  Chromium and by page tests; how "Start" (two phrases and the note about a new session
  between them) and "Connect an agent" look in Safari has not been seen.
- **The update was checked from a local registry, not from ghcr.io.** An installation on
  v0.6.0 with a seeded `START`, a second project and a second account was updated by its
  own updater to images built from this code: services healthy, updater recreated, no
  orphan containers, no `previous` tags, project and task counts and introduction state
  unchanged. The real `stable` channel and the release tag were not part of that run, and
  only the path from v0.6.0 was tried, not from older releases.
- **Rolling back a bad release after the updater fix was not run live.** The rule that the
  previous updater can now finish its rollback rests on tests with a stand-in `docker`.
- **A running (not stopped) orphan service and the update done by the updater alone,
  without an updater replacement, were covered by tests only.**
- **`install.ps1` was never executed by PowerShell**; its output was compared with
  `install.sh` by reading and by text tests.
- **Explanations on screens other than the task list and the inbox after "Skip"** were
  checked through the shared server flag, not screen by screen. A second browser was a
  fresh Playwright context, not a second device.
- **The board's web server behind a DNS that is not Docker's internal one** was not tried.
