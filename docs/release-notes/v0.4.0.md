# Casefile v0.4.0

Draft — the coordinator fills in the rest of this release's notes.

## Breaking changes

These change the MCP and REST contracts.

1. **`link`, `unlink` and the registry tools answer with only what changed.**
   `link`/`unlink` now return `{key, entry, other_entry}` — the case entry numbers filed
   on both sides — instead of echoing `key`/`kind`/`other` and, for `unlink`, a
   `removed: true` flag. `create_project`/`update_project` return `{key}`;
   `register_participant`/`update_participant` return `{name}` — instead of the object's
   fields in full. (`TRK-144`)
2. **The queue is now a project, everywhere, with no aliases.** The table, the REST
   routes (`/api/v1/projects`, `/api/v1/projects/{project_key}`), the `project` parameter
   of task creation, search, questions, remarks and the journal, `bootstrap.projects`, the
   `project:` field of the query language, the MCP tools `list_projects`, `get_project`,
   `create_project`, `update_project` and the `project` argument of `create_task`,
   `search_tasks` and `wait_journal`, and the error codes `project_not_found`,
   `project_key_taken`, `invalid_project_key`. Nothing answers to the old `queue` names.
   Task keys (`TRK-42`) and entry references (`TRK-42#3`) are unchanged; the migration
   renames in place and keeps every row. Migration archives taken from v0.3 are still
   accepted by the import. (`TRK-152`)

**For agents:** the `tracker-agent` skill and the `tracker-discipline` prompt are no
longer served (`TRK-146`). If you copied the skill to disk before this release (for
Claude Code, `~/.claude/skills/tracker-agent/SKILL.md`), delete it — the rules it held
now arrive in the MCP `instructions` and in each tool's own description.
