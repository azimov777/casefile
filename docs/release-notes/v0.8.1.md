# Casefile v0.8.1

A patch release. It fixes how an installation that was set up before v0.8.0 (or kept
current only by its hourly self-update) learns about the Casefile skill, raises the tool
timeout in the Codex connection block, completes the tool metadata, and fixes one flaky
interface behaviour. No database migration, no change to tool names, arguments or error
codes.

## Install

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/azimov777/casefile/main/install.sh | sh
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/azimov777/casefile/main/install.ps1 | iex
```

All you need is Docker. An installation on v0.8.0 updates itself to this release within
about an hour, or at the next Docker start.

## Do this once if your installation is older than v0.8.0

The skill is installed by the installer, not by the updater. The hourly self-update
replaces Casefile's images and nothing on your machine, so an installation made before
v0.8.0, and any machine that was only updated by the updater, **has no Casefile skill**.
Do one of these once:

- run the install line above again (it installs the skill into every agent harness it
  finds: Claude Code, Codex, Hermes and others through `npx skills`); or
- install only the skill, without touching the service:

  ```bash
  curl -fsSL https://raw.githubusercontent.com/azimov777/casefile/main/install.sh | CASEFILE_SKILL_ONLY=1 sh
  ```

  This is also the line for a machine that only connects to a Casefile running elsewhere.

Your agent now sees this on its own: the MCP `instructions` tell it to check whether the
`casefile` skill is installed in its harness and to install it if it is not, and the guide
(`docs/agent-install.md`), `skills/casefile/SKILL.md` and `README.md` spell out the check and
the commands per harness.

## What's changed

- **The skill check is explicit.** `docs/agent-install.md` has a step that checks whether the
  skill is present in each harness (Claude Code, Codex, Hermes, the `~/.agents/skills`
  directory used by `npx skills`) and what to run if it is not, including for a service that
  is already installed and updated. `skills/casefile/SKILL.md` and `README.md` say the same.
- **Codex: `tool_timeout_sec = 90`.** Codex gives an MCP tool 60 seconds to answer by
  default, and `wait_journal` can wait up to 60 seconds, so a long wait could be cut by the
  client. The `[mcp_servers.casefile]` block printed by both installers, in the guide, in the
  skill and on the "Connect an agent" and "Access" screens now sets `tool_timeout_sec = 90`.
  An existing `~/.codex/config.toml` is not edited: add the line to the block yourself if you
  use long waits.
- **Every tool has a `title`.** All MCP tools declare a short human-readable `title` next to
  their behaviour hints, and a test fails on a tool without one. Names, descriptions and
  arguments are unchanged.
- **The skill extension follows the final SEP-2640.** The server's `skills` extension was
  checked against the final text of SEP-2640; the one difference, the limits on the size of a
  skill it will serve, is corrected, and a skill over the limits is not offered.
- **`wait_journal` on the 2026-07-28 protocol revision.** Checked on both revisions, 2025-11-25
  and 2026-07-28: it needs no protocol session and no SSE resumption, and a call that is
  interrupted and repeated with the same cursor neither loses nor duplicates entries. No
  defect was found; the behaviour is pinned by tests.
- **`claude plugin validate --strict` runs in CI.** The plugin manifests are validated on every
  pull request and before a release is published.
- **Interface: a typed filter field is no longer erased.** Text typed into the assignee
  filter right after another condition was applied could be wiped by a late address change;
  it is kept now. A contrast measurement on the task card waits for the page to settle.

## For agents

- **MCP `instructions`:** the pointer to `skill://casefile/SKILL.md` now says it covers
  "installing the casefile skill if the harness lacks it". To make room, five sentences were
  shortened without dropping a rule.
- Tool contracts, error codes and `openapi.json` paths are unchanged.

## Upgrade notes

- **No database migration.** Your data and accounts are left as they are.
- **Install the skill once** if the installation is older than v0.8.0 (see above).
- **Codex:** add `tool_timeout_sec = 90` to your `[mcp_servers.casefile]` block if you set
  it up by hand; the installer does not rewrite an existing Codex config.
- **`CASEFILE_VERSION`** in `.env`, if you pin a release, is the only thing to change to move
  to this one by hand.

## Not verified yet

- **No model was run on the new instructions pointer.** That a model in a live session reads
  the resource and installs the skill, and that Codex supports MCP resources, was not
  measured. The check commands come from `install.sh` and were not run on live harnesses.
- **`tool_timeout_sec` showed no effect in a measurement.** On Codex CLI 0.159.2 a
  60-second `wait_journal` was not cut even without the line, so the line rests on Codex's
  documented default. The Codex desktop app (its connection form has no such field) and older
  CLI versions were not tried.
- **The skill validation job was not run in GitHub Actions**; the same command passed locally.
- **`wait_journal` was checked with the SDK client over ASGI**, not across a network or a
  proxy, and not from a live Claude Code session.
- **The `title` texts were not checked against any catalog**: how Anthropic's and OpenAI's
  catalogs read them was not tried.
- **The flaky task-card contrast failure was never reproduced**; its cause was found in code.
  The filter field failure was reproduced and fixed.
