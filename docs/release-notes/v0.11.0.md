# Casefile v0.11.0

A release about **directions**: a part of a project's work that has no end (promotion,
commerce, support) now has a place of its own, with its own case and attributes, instead of
an umbrella task that never closes. Checks of a task are also frozen once work on it has
begun, a local installation now attributes OAuth connections to the person at the machine,
and `get_task` opens with a computed "state" block that gets an agent into a task for a
fraction of the tokens.

## Install

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/azimov777/casefile/main/install.sh | sh
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/azimov777/casefile/main/install.ps1 | iex
```

An installation on v0.10.0 updates its service to this release by itself within about an
hour, or at the next Docker start. This release has two migrations (see "Upgrade notes");
the updater takes its database snapshot before them.

## What's changed

- **Directions.** A direction lives inside one project and is addressed `PROJECT/key`
  (for example `TRK/promotion`). It has a card (title, description up to 320 characters),
  attributes with history, a case of its own and an archive; it has no status and is flat
  (no direction inside a direction). The project tools take the address in place of a
  project key: `create_project`, `update_project`, `get_project`, `archive_project`,
  `restore_project`, `set_attribute`, `remove_attribute`, `add_project_entry` and
  `read_project_entries`. An archived direction freezes its card, attributes and case; only
  restoring it works (TRK-555).
- **The `direction` field of a task.** One optional direction of the task's own project:
  set in `create_task`, changed in `update_task`, shown in `get_task` and in search rows,
  and cleared when the task moves to another project. Search selects by it:
  `direction: TRK/promotion` or `direction: empty()` (TRK-556).
- **Directions in the interface.** The task card shows the direction and lets a person
  change it next to the priority; the task list filters by direction (and by "no
  direction"); the project page has a "Directions" section (create, edit, archive and
  restore with a reason); a direction page shows the card, attributes with history, the
  case, and the direction's tasks; a person writes notes and decisions there as in a
  project's case. Links like `TRK/promotion#3` open the direction page (TRK-557).
- **Checks are frozen after the first entry into `in_progress`.** `update_task` and
  `PATCH /api/v1/tasks/{key}` refuse to change `checks` or one `check` of a task that has
  entered `in_progress`: `409 task_checks_frozen`, with the task key and the number of the
  entry of the first entry into work. A check that cannot be run is closed with the
  `unverifiable` outcome (which files a `warning`), not rewritten. Other sections are
  edited in `backlog` as before (TRK-562).
- **OAuth: a new sign-in replaces the old connection.** When the same client signs in again
  for the same participant, its previous connection is disconnected, so abandoned
  connections no longer pile up in "Access" (TRK-560).
- **OAuth in local mode belongs to the person at the machine.** In the default local mode
  (no login), connections and agent keys issued by the installation are attributed to the
  person at the machine, not to "installation", so they appear under "Access" → "Mine". On
  every start the `local-token` step moves live `oauth` and `key` tokens issued by the
  tracker to that person; revoked tokens and sessions are not touched. Network mode
  (`CASEFILE_LOGIN=password`) is unchanged (TRK-559).
- **`state` first in `get_task`, and `get_task(brief=true)`.** `get_task` (MCP and
  `GET /api/v1/tasks/{key}`) opens with a computed `state` block: the last transition and its
  reason, `next_step` and `blockers` of the last summary, the last entries after it, open
  questions and remarks with addressees, blockers, children by status, decisions filed
  after the card. Nothing is stored or written for it. `brief=true` returns only the
  header, parent, features, `state` and transitions, in about 600 tokens or fewer; call
  without `brief` to take a task into work, since the sections are needed. The task card in
  the interface shows the same block as "Now". The `tools/list` text grew by about 900
  tokens (TRK-579).
- **The "Waiting for an answer" filter in the task table.** A checkbox in the "Filter"
  panel replaces the lost "status: waiting" switch (TRK-577).
- **REST and MCP read the case the same way.** A decision without `supersedes` and an edit
  of a section without `check_no` read identically through both doors (TRK-565).
- **Plugin catalogs find the connector.** A root `mcp.json` (Open Plugins standard, same
  content as `.cursor-plugin/mcp.json`) rides in the `plugin` branch so that catalog
  auto-scans such as cursor.directory find the connector by themselves. There is
  deliberately no `.mcp.json` with a dot: Claude Code reads that as a project setting for
  anyone who opens a clone (TRK-584).
- Internal: the error texts of `task_checks_frozen` in the interface dictionaries, repository
  map lines for new tests and the migration, and `pnpm check` on a branch that edits
  `docs/ERRORS.md` or `openapi.json` (TRK-581, TRK-582, TRK-583).

## Upgrade notes

- **Update the clients.** Open Claude Code sessions keep the old tool schemas (no `direction`
  field, no `brief`): run `/mcp` and reconnect, or start a new session.
- **Two migrations**, one head: `3cc02e043842` (the `directions` table) and `7be41d95c0a2`
  (`tasks.direction_id`, empty for every existing task), both after `a9cb1ec147c4`. No data
  is moved. The updater's snapshot (`updater-snapshot` volume) is taken before them.
- **New error codes** (see `docs/ERRORS.md`): `task_checks_frozen`, `direction_not_found`,
  `direction_archived`, `direction_key_taken`, `direction_not_archived`,
  `direction_description_too_long`, `direction_project_mismatch`,
  `direction_reason_required`, `invalid_direction_key`. The REST schema in `openapi.json`
  changed (directions, the `direction` field, `state`, `brief`).
- **Existing umbrella tasks stay as they are.** Moving them into directions is a manual
  step on each installation; nothing is converted automatically.
- **Local installations:** connections made before the update are attributed to the person
  at the machine on the first start of this release.
- **The plugin text comes with the install line.** The hourly self-update changes the
  service only; run the install line again (or `CASEFILE_SKILL_ONLY=1` for the plugin alone)
  to get the new manifests and skill text.
- **`CASEFILE_VERSION=0.10.0`** in `.env`, if you pin a release, is the line to change to
  move to this one by hand.

## Not verified yet

- **The interface was run in Chromium only**, not in Safari: the direction page, the
  "Directions" section, the direction cell and dialog in the task card, the "Now" block
  (on a wide screen and at phone width), and the "Waiting for an answer" filter.
- **Live agents were not measured with `brief` and `state`.** There is no blind test that an
  agent using `brief` will not skip the sections when it must take a task into work; the
  tokens were counted on synthetic tasks (the average-case upper bound was 657 against the
  600 target), and whether Claude Code puts the output schema into the context was not
  checked.
- **Live Claude Code and Cursor were not tried on the root `mcp.json`**, only the
  documentation was read; no re-scan was done on cursor.directory. Other tools that read
  `mcp.json` without a dot as a project setting are a theoretical risk.
- **Local-mode attribution was tested on a database, not on a live installation**: the
  "Access" → "Mine" screen after the update was not looked at with real connections.
- **Frozen checks were not run against old cases** with rewritten checks; the outdated-verdict
  mark is covered only on tasks that never entered work.
- **The live refresh of a direction page** by a journal frame is covered by unit tests only,
  with no end-to-end scenario; the English texts of the new screens are tested through the
  dictionary, not walked through in the end-to-end set.
- **Moving umbrella tasks into directions** (TRK-558) on the owner's installation waits for
  this release.
- The items of v0.9.0's to v0.10.0's "Not verified yet" are still open.
