# Casefile v0.9.2

A patch release around the installer. The plugin marketplace is now installed from a
dedicated branch, the installer remembers non-default ports, Hermes connects with OAuth,
and the project has public pages for directory listings.

## Install

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/azimov777/casefile/main/install.sh | sh
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/azimov777/casefile/main/install.ps1 | iex
```

An installation on v0.9.1 updates its service to this release by itself within about an
hour, or at the next Docker start. The service has no migrations and no new settings.

## If the plugin is already installed

The plugin marketplace used to be added from the `stable` branch. That branch carries the
whole repository, and the harnesses copied its root files into the plugin cache. The
marketplace now comes from the `plugin` branch, which holds the plugin files only.

An existing installation is moved by running the install line above again (to touch only the
plugin and the skill, add `CASEFILE_SKILL_ONLY=1`; for a server that is not on this machine
also `CASEFILE_URL=<address>`). The installer notices the old source and replaces it: in
Claude Code it drops only the marketplace declaration in `settings.json`, so the plugin and
its settings stay; in Codex it removes the marketplace and adds it again. The hourly
self-update does not do this: it updates the service only. Without the installer:

```bash
claude plugin marketplace add azimov777/casefile#plugin
```

## What's changed

- **The plugin marketplace is installed from the `plugin` branch**, without `--sparse`.
  The installers, the guide, the skill and the **Connect an agent** screen all use it
  (TRK-494).
- **Non-default ports and the project name are written to `.env`.** If you name
  `CASEFILE_PORT`, `TRACKER_MCP_PORT` or `COMPOSE_PROJECT_NAME` to the installer, they land
  in the new installation's `.env`, so the updater and `docker compose up` keep them. The
  `.env` of an existing installation is not changed (TRK-493).
- **Hermes connects with OAuth**: the installer prints a block with `auth: oauth` for
  `~/.hermes/config.yaml`. The agent key stays as the fallback for clients without OAuth.
  The device sign-in is not supported (TRK-495).
- **Public pages** for directory listings are published on GitHub Pages at
  `https://azimov777.github.io/casefile/`: the home page, privacy, terms and support
  (TRK-462).

## Upgrade notes

- No migrations and no new settings.
- **`CASEFILE_VERSION=0.9.2`** in `.env`, if you pin a release, is the line to change to move
  to this one by hand.
