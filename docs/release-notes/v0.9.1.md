# Casefile v0.9.1

A fix for signing in through the plugin. On v0.9.0 the `casefile` plugin's default address,
`http://127.0.0.1:8100/mcp`, could not sign in: both Claude Code and Codex refused with a
resource mismatch, because the service named itself `localhost` in its OAuth metadata while
the client had connected to `127.0.0.1`. This release fixes the service.

## Install

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/azimov777/casefile/main/install.sh | sh
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/azimov777/casefile/main/install.ps1 | iex
```

An installation on v0.9.0 updates its service to this release by itself within about an
hour, or at the next Docker start. Nothing changes on the agents' side: the plugin and its
address stay as they are.

## If sign-in failed on v0.9.0

After the service has updated, sign in again. No reinstall and no new address are needed.

- **Claude Code:** in a session, `/mcp` → `casefile` → **Authenticate**.
- **Codex:** `codex mcp login casefile`.

An agent that connects with a key is not affected.

## What's fixed

- **Sign-in at `127.0.0.1` works.** On a machine's own loopback (`localhost`, `127.0.0.1`
  or `[::1]`, same port as the public address) the service now names itself by the host the
  client used: the protected-resource document, the authorization-server metadata, the
  `resource_metadata` pointer in `401` and `iss` on the `/authorize` redirect (TRK-488).
  Outside loopback, in network mode (`https` or `TRACKER_LOGIN=password`) and for any other
  host or port the documents are unchanged.
- **`resource` (RFC 8707) is checked against the service address** on `/authorize` and
  `/token`; the loopback hosts count as one (TRK-485).
- **`scopes_supported` and `scope` in `401`.** The resource document lists the scope and the
  `WWW-Authenticate` challenge carries `scope="casefile"`, so clients that ask for scopes
  from the challenge get one (TRK-484).

## Upgrade notes

- No migrations and no new settings.
- **`CASEFILE_VERSION=0.9.1`** in `.env`, if you pin a release, is the line to change to move
  to this one by hand.

## Not verified yet

- **A full sign-in in Claude Code** on the loopback address was not completed in the
  measurement: it reaches the authorization code on the callback, then stops at the macOS
  Keychain of an isolated test profile, as it does with `localhost`. Codex CLI signed in
  and listed all 30 tools on `127.0.0.1`.
- The items of v0.9.0's "Not verified yet" (long-lived sessions, desktop apps, a real TLS
  proxy, `install.ps1` end to end) are still open.
