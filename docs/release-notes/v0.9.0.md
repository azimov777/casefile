# Casefile v0.9.0

Agents now sign in. Claude Code and Codex connect to Casefile through the `casefile`
plugin and an OAuth sign-in: no token is copied, and none is written into their
configuration. Behind it is a simpler access model: an agent has one kind of access that
opens every tool, and a person only signs in to the board. **Read "Before you update"
first:** the update revokes keys that were issued to people.

## Install

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/azimov777/casefile/main/install.sh | sh
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/azimov777/casefile/main/install.ps1 | iex
```

All you need is Docker. An installation on v0.8.x updates its service to this release by
itself within about an hour, or at the next Docker start. The plugin and the sign-in on
your agents' side are not updated by the updater: run the install line once (below).

## Before you update

- **Keys issued to people stop working.** The update revokes every key that belongs to a
  person: the `bootstrap` key printed by `init`, keys made with `issue-token --participant
  <person>`, and keys issued to a person on the **Access** screen. A client or script that
  uses one gets `401` with the reason `token_revoked`. Board sessions, this machine's board
  key and every agent key stay valid.
- **Agent keys keep working, with full rights.** The key the installer gave your agent
  (participant `agent`) and every key you issued to an agent, `task` or `main`, go on
  working, and each now opens every tool.
- **If a script of yours used your own key**, register an agent for it on **Access**, issue
  that agent a key and put the key in the script.

## After you update: do this once on each agent machine

1. **Run the install line again** (above). It installs the `casefile` plugin into Claude
   Code and Codex with this installation's address, removes the old manual `casefile`
   (or `tracker`) MCP entry with a token in it if it points at this installation, and signs
   the agents in. A machine that only connects to a Casefile running elsewhere needs only the
   plugin and the sign-in:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/azimov777/casefile/main/install.sh | CASEFILE_SKILL_ONLY=1 sh
   ```

   Add `CASEFILE_URL=https://<your MCP host>/mcp` for a server that is not on this machine.

2. **Sign in, if the installer could not.** Without a terminal for the sign-in it prints the
   commands; run them once:

   ```bash
   claude mcp login plugin:casefile:casefile
   codex mcp login casefile
   ```

   In a Claude Code session the same is `/mcp` → `casefile` → **Re-authenticate**. On your
   own machine the sign-in asks for nothing: Claude Code acts as `claude`, Codex as `codex`.

3. **Clients without OAuth keep using a key.** Hermes, scripts, a journal watcher that runs
   between sessions, and any client that cannot sign in with MCP OAuth connect with an agent
   key in the `Authorization` header, as before. On your own machine it is the key the
   installer prints (read it again with
   `docker compose run --rm --no-deps -T agent-token cat .secrets/agent-token` in
   `~/casefile`); otherwise issue one to an agent on **Access**.

## What's new

- **Sign-in with OAuth.** The MCP service is now an OAuth 2.1 protected resource and its
  own authorization server: a client without a token gets `401` with a pointer to the
  metadata, registers (dynamic registration or a client metadata document), signs in with
  PKCE and receives a connection token with `expires_in` and a refresh token. A connection
  lasts 30 days by default (`TRACKER_OAUTH_ACCESS_TTL`) and is renewed by the client without
  a new sign-in; a refresh token is single-use and rotated. `/authorize` answers with `iss`
  (RFC 9207). Bearer keys work exactly as before for clients that do not sign in.
- **The `casefile` plugin carries the connection.** Besides the skill, the plugin for Claude
  Code (`.claude-plugin/`) and Codex (`.codex-plugin/`) now holds the MCP connector: the
  installation's address and no token. The installer sets the address; the plugin manifest
  is ready for Anthropic's and OpenAI's plugin catalogs (`claude plugin validate --strict`
  passes, a ZIP for OpenAI is built by `scripts/build-openai-plugin.sh`).
- **One kind of agent access.** The `task` and `main` token scopes are gone. Any agent, over
  MCP or REST, can do everything a `main` token could: create projects, register
  participants, move tasks. Issuing and revoking access still needs a person with an account.
- **A person only signs in.** No key is issued to a person any more: `POST /api/v1/tokens`
  and `issue-token` refuse a person with `human_token_not_allowed`, and `init` creates the
  owner and the administrator account without printing a token. Every row of access has a
  kind: a sign-in **session**, an agent **key**, or an OAuth **connection**.
- **The Access screen, rebuilt.** **Access** lists every way in, in three sections: agent
  connections (OAuth sign-ins), agent keys and sign-in sessions — who each speaks for, who
  issued it and when it was last used. A connection is disconnected there, and that also
  ends its refresh chain; a key is revoked. Keys are issued to agents only.
- **Connect an agent, without a key.** The **Connect an agent** screen shows the plugin and
  sign-in commands for Claude Code and Codex; a key appears only in the snippets for clients
  without OAuth.
- **Network mode: everyone connects their own agents.** With sign-in on and the MCP address
  on `https`, a client opens a sign-in page on the MCP host: the person signs in with email
  and password and picks which agent the client acts as. By default it is their own agent,
  created on the first sign-in — Alice's Claude Code signs as `claude_alice`, her Codex as
  `codex_alice`. An agent has an owner: a person sees and disconnects the connections and
  keys they issued or that speak for their agents, and only an administrator can issue a key
  to someone else's agent (`agent_owned_by_another`). Disabling a person's account revokes
  everything they issued. On a machine of your own the sign-in is immediate, and only while
  the ports are on localhost. Over plain `http` beyond localhost there is no OAuth: agents
  use keys. The proxy setup is in README, **Network mode**.
- **`CASEFILE_SKILL_ONLY=1` without an address** installs the plugin with the default local
  address instead of skipping it, so Claude Code and Codex never lose the skill.
- **Release pipeline.** The `stable` branch is moved by the run on the `main` push, and a
  narrow `plugin` branch with only the plugin files follows it for Anthropic's portal.
- **The skill's description is shorter**, with its trigger first, to fit the harnesses'
  listing limits.

## For agents

- **No scopes.** `tools/list` shows every tool to every agent token, and a former `task`
  token no longer gets `permission_denied` for a project, participant or move tool. Two new
  error codes: `human_token_not_allowed` and `agent_owned_by_another`.
- **`401` names its reason** on MCP too: `error_description` of `WWW-Authenticate` and
  `details.reason` carry `token_revoked`, `unknown_token`, `token_expired` or
  `account_disabled`. An OAuth client on `token_expired` renews with its refresh token.
- **MCP `instructions`, the guide (`docs/agent-install.md`), `skills/casefile/SKILL.md` and
  README** describe connecting through the plugin and the sign-in; the agent key is for
  clients without OAuth.

## Upgrade notes

- **Six database migrations**, applied by the update itself: OAuth clients, codes and
  refresh tokens; client metadata documents; the token scope column is dropped; agents get
  an owner; every token gets a kind; keys of people are revoked. The updater takes a
  database snapshot first and restores it if the release fails to start. Going back to
  v0.8.x after this update is not supported: revoked keys stay revoked.
- **New settings** (all optional, see `.env.example`): `TRACKER_OAUTH_ACCESS_TTL` (connection
  lifetime, `P30D`), `TRACKER_OAUTH_DOCUMENT_FETCH_LIMIT` and
  `TRACKER_OAUTH_DOCUMENT_REFUSAL_TTL` (client metadata document fetching).
- **`CASEFILE_VERSION=0.9.0`** in `.env`, if you pin a release, is the line to change to move
  to this one by hand.

## Not verified yet

- **Sign-in in live clients over time** — Claude Code with the macOS Keychain, the Codex and
  Claude Code desktop apps, a refresh after 30 days, a sign-in that survives a service
  restart — was not measured; it is a task of its own (TRK-453). The protocol was run by
  tests, `curl` and a Codex CLI sign-in on a local installation.
- **`install.ps1` was not run end to end**: on the test machine PowerShell runs only under
  emulation, where the previous installer fails too. Its steps were run one by one.
- **Network mode behind a real TLS proxy** (Caddy or nginx with certificates) was not set
  up; the sign-in page was checked in Chromium, not in Safari.
- **The update from v0.8.1** was run on a separate installation from the published v0.8.1
  images to images built from this release's commit, not through the published `stable`
  channel.
