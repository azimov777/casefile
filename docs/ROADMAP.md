# Порядок выполнения задач

Задачи лежат в `tasks/`. Номер файла — рекомендуемый порядок, но реальное ограничение —
зависимости: задачу можно брать, когда выполнены все, от которых она зависит.

## История

Задачи 01–19 построили трекер общего назначения. 2026-09-03 владелец решил переписать
доменный слой под трекер для агентов (`CONCEPT.md`), и задачи 20–29 это переписывание
выполнили: снос старого домена, участники и токены с наборами, задача и дело, связи,
поиск, лента с ожиданием и SSE, идемпотентность, MCP-сервер, сборка с `bootstrap`, демо
и `openapi.json`. Ревизия 2026-09-04 по коду и концепции расхождений не нашла и завела
задачи 30–34 на найденные дыры: очередь изменений, область вердиктов, признаки в списке,
документационный долг, чтение `.env` в прод-контуре. Задача 35 вычистила документацию от
следов снесённого домена. Все закрыты, очередь `tasks/` пуста.

Дальше работа идёт не по плану, а по наблюдениям: главная точка — агент, работающий через
MCP с установленным скилом. Видно по делу, какие записи он пишет сам, а какие приходится
вытягивать текстом скила.

## Что откладывается до наблюдений

Решения, которые владелец пометил как временные и вернётся к ним после экспериментов:

- Поле «исполнитель» как свободная строка без валидации.
- Две формы идентичности агента: постоянный участник и временная метка.
- Прямой переход `in_progress → backlog`: оставлен, но за частотой стоит следить.
- Статус `review`: наблюдение получено, решение принято 2026-09-05 — статус снят,
  обзорные проверки прогоняет исполнитель в `in_progress`, вердикты требуются перед
  `done` (`CONCEPT.md`, 6; задача `TRK-4`).
- Роль человека в системе целиком.
- Вебхуки: вернуть, если назначателю не хватит ленты. Материал по подписи, повторам
  доставки и окну переподключения — в `notes/webhooks.md`.
