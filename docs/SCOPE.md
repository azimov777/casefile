# Объём системы: что было заложено в ТЗ

Полный перечень того, что описывалось в исходном ТЗ и реализовано по задачам 01–19.
Документ отвечает на вопрос «что вообще есть в системе», без деталей реализации.

Статусы: **есть** — работает; **удаляется** — вычеркнуто ревизией объёма, см. `SCOPE-REVISION.md`.

## 1. Акторы и доступ

| Возможность | Статус |
|---|---|
| Акторы трёх типов: человек, агент, система | есть |
| API-токены с хешированием, отзывом, отметкой последнего использования | есть |
| Аутентификация запроса по токену, единая для REST и MCP | есть |
| Единая точка проверки прав (в текущем режиме разрешает всё) | есть |

Ролевой модели нет: режим «один владелец и его агенты».

## 2. Очередь и конфигурация процесса

| Возможность | Статус |
|---|---|
| Очередь с ключом, владельцем, счётчиком номеров без гонок | есть |
| Редактируемые типы задач, статусы, резолюции — не зашитый справочник | есть |
| Категория статуса (`new` / `in_progress` / `done`) как основа для досок, прогресса и правил | есть |
| Область справочника: глобальный или локальный для очереди | есть |
| Конфигурация очереди целиком одним запросом | есть |
| Запрет удаления статуса с задачами, перенос задач в другой статус | есть |
| Резолюции как отдельный справочник | удаляется |

| Типы значений: строка, текст, число, дата, дата-время, флаг, перечисление, актор, ссылка на задачу | есть |
| Хранение значений в JSONB с фиксированным форматом сериализации | есть |
| Валидатор, возвращающий все ошибки сразу, а не первую | есть |
| Применимость поля к связке «очередь + тип задачи» | есть |
| Запрет смены типа поля с данными, мягкое скрытие вместо удаления | есть |

## Чего в системе нет и не планировалось

Учёт времени и Story Points, вложения файлов, дашборды и отчёты, роли и разграничение доступа,
мультиарендность, цели и ключевые результаты, почта и мессенджеры, импорт из внешних трекеров.
