# docs

Проектная документация бэкенда таск-трекера: что строим, по каким правилам и в каком порядке.
Точка входа для нового агента — `CONCEPT.md`, затем `CONVENTIONS.md`, затем свой файл задачи.

## Папки
- `notes/` — находки и грабли от предыдущих агентов; читается до начала работы, только пополняется
- `tasks/` — задания для агентов-исполнителей, по одному файлу на задачу; выполненные удаляются

## Файлы
- `CONCEPT.md` — доменная модель, механики и границы объёма; отвечает на «что и почему»
- `ERRORS.md` — справочник кодов ошибок с описанием, когда какой возникает; собирается командой
- `FRONTEND.md` — документ для разработчика интерфейса: оболочка, аутентификация, экраны, SSE
- `CONVENTIONS.md` — обязательные правила: стек, слои, контракт API, события, тесты, коммиты,
  протокол выполнения задачи
- `ROADMAP.md` — порядок запуска задач, граф зависимостей, отметки о выполненном
- `SCOPE.md` — перечень возможностей системы с пометкой, что есть и что вычёркивается
- `SCOPE-REVISION.md` — решение о сокращении объёма: что удаляется, что остаётся и почему
