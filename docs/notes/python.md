# Python и библиотеки

## pydantic-settings разбирает списки как JSON до валидаторов

**Что:** поле `list[str]`, заданное переменной окружения через запятую, роняет запуск:
`SettingsError: error parsing value for field "cors_origins"`. Валидатор с `mode="before"`
не спасает — источник настроек пытается разобрать значение как JSON раньше него.
**Почему важно:** симптом выглядит как ошибка валидации, хотя валидация даже не началась.
**Как правильно:** пометить поле `Annotated[list[str], NoDecode]` и разбирать строку самому
в `field_validator(mode="before")`. Либо всегда писать в окружении JSON-массив.
**Где:** `app/core/config.py`, поле `cors_origins`.

## RUF001 работает сторожем языка сообщений

**Что:** `RUF001` ругается на кириллицу в строковых литералах, `RUF002` — в докстрингах,
`RUF003` — в комментариях. В проекте отключены только два последних.
**Почему важно:** сообщения об ошибках, описания схем и логи обязаны быть английскими, а
докстринги и комментарии — русские. `RUF001` разделяет эти два мира автоматически: русский
текст, случайно попавший в сообщение об ошибке, не пройдёт линтер.
**Как правильно:** не добавлять `RUF001` в `ignore`, чтобы обойти находку, — переводить строку.
Остальную группу `RUF` тоже не отключать: `RUF012` ловит реальные ошибки.
**Где:** `pyproject.toml`, `[tool.ruff.lint]`.

## Атрибуты SQLAlchemy объявляются через ClassVar

**Что:** `type_annotation_map = {...}` в наследнике `DeclarativeBase` даёт `RUF012`.
**Почему важно:** очевидное «решение» — навесить `noqa`; правильное — аннотация
`ClassVar[dict[Any, Any]]`, которую декларативный слой SQLAlchemy пропускает при разборе
модели и не пытается превратить в колонку.
**Где:** `app/db/base.py`, класс `Base`.
