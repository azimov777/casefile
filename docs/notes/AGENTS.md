# docs/notes

Накопленное знание по проекту: находки, грабли и неочевидные решения, оставленные агентами для
тех, кто придёт следующим. Один файл на область. В отличие от `docs/tasks/`, заметки только
копятся и не удаляются. Формат записи — в `docs/CONVENTIONS.md`, раздел «Заметки».

## Файлы
- `api.md` — HTTP-слой: схема авторизации, защита роутера по умолчанию, форма ответов
- `automation.md` — движок правил: след автоматики в событии, три защиты от цикла, журнал срабатываний, синхронизация реестра
- `boards.md` — доски: совмещённая шкала порядка, перенумерация, границы ранга и колонки
- `comments.md` — обсуждение: упоминания, мягкое удаление, разреженные позиции чеклиста, теги
- `db.md` — PostgreSQL, SQLAlchemy, Alembic: ключи, ограничения, перечисления, пагинация, миграции
- `docker.md` — сборка образов и контуры compose: слои зависимостей, различия dev и prod, порядок старта
- `journal.md` — лента: порядок `seq` против порядка фиксации, оповещение из транзакции, чтение кадров в тестах
- `links.md` — связи задач: чья роль в имени вида, два графа циклов, порядок записей в двух делах; ниже — прежняя модель
- `mcp.md` — MCP-сервер: версии протокола и подписки, контекст ресурсов, частичные изменения, порядок настройки процесса, приложение в тестах
- `notifications.md` — инбокс и подписки: адресация по нагрузке, склейка, три уровня оповещения ожидания
- `retention.md` — срок хранения журналов: пол окна SSE, удаление пачками, журнал исчезнувшего правила
- `search.md` — отбор задач: одно представление на два входа, вычисляемые признаки в запросе, порядок и курсор; ниже — прежняя модель
- `tasks.md` — задача и дело: точки подключения проверок перехода, единая точка мутаций, автор служебных записей
- `teardown.md` — снос задачи 20: что признано фундаментом, что удалено «инфраструктурного» и где это взять
- `webhooks.md` — каналы наружу: два уровня повторов, подпись, мёртвый адрес, окно переподключения потока
- `python.md` — поведение библиотек: pydantic-settings, ruff, декларативный слой SQLAlchemy
- `testing.md` — инфраструктура тестов: откат транзакций, цикл событий, тестовая база, проверка гонок
- `workflow.md` — целостность назначения и живого графа, резолюции, статус очереди по умолчанию, миграция
