# 31. Вердикты считаются только в текущем обзоре

**Ожидает решения владельца: задача меняет правило концепции.** Пока решение не принято,
задачу не брать. Если владелец отклонит, файл удаляется, а риск описывается
в `notes/tasks.md`.

## Цель

Убрать наследование старых вердиктов. Сейчас `review → done` смотрит на последний
вердикт по каждому номеру проверки за всю жизнь задачи. После возврата `review → open`
и переделки работы, или после правки `checks` в `backlog`, старые `passed` продолжают
засчитываться, хотя проверялся другой выход или другая проверка.

## Контекст

- `CONCEPT.md`, 3.3, строка валидации `review → done`; 3.4, запись `verdict`.
- Реализация: `app/db/repositories/entries.py`, `last_verdict_outcomes` (`DISTINCT ON
  (check_no) ORDER BY check_no, seq DESC` без нижней границы по `seq`).
- Образец правила с нижней границей уже есть: сводка считается только после последнего
  входа в `in_progress` (`has_summary_since`).
- Два варианта границы. **Рекомендуемый:** вердикт засчитывается, только если подшит
  после последнего входа задачи в `review`; каждый обзор проверяет текущий выход целиком.
  Мягкий: только после последней правки `checks`; закрывает случай переписанной
  проверки, но не случай переделанного выхода.

## Ограничения

- Реализовать через ту же точку подключения проверок перехода, что и сводка; таблицу
  переходов не трогать.
- Старые вердикты остаются в деле как история; меняется только то, какие из них
  участвуют в валидации.
- Ошибка `checks_not_passed` по-прежнему перечисляет проверки без положительного
  вердикта в текущем обзоре.

## Выход

- Валидация с нижней границей по выбранному варианту; `CONCEPT.md` 3.3 и `SKILL.md`
  (раздел «Проверка чужой работы») уточнены одной фразой; заметка в `notes/tasks.md`.
- Тесты, демо-данные при необходимости поправлены.

## Обзорные проверки

1. Задача в `review` с `passed` по всем проверкам уходит `review → open` с причиной, снова проходит `in_progress → review`; переход в `done` отвечает `checks_not_passed` со всеми номерами, пока не подшиты новые вердикты.
2. Задача возвращается в `backlog`, `checks` переписаны, задача доходит до `review`; старые вердикты не засчитываются.
3. В пределах одного обзора `failed`, затем `passed` по той же проверке даёт `done`.
4. Полный набор тестов зелёный; `docker ps` чист после работы.
