# 03. Очереди, типы задач, статусы

- **Блок:** Очереди
- **Зависимости:** 01, 02
- **Результат:** можно создать очередь с настроенным процессом

## Зачем

Очередь — центральная единица конфигурации: она владеет набором типов задач, воркфлоу и
локальными полями. Всё остальное строится вокруг неё.

## Объём

- Справочники: `IssueType` (ключ, название, иконка), `Status` (ключ, название, **категория**:
  `new` / `in_progress` / `done`), `Resolution` (ключ, название).
- Справочники **редактируемые**: пользователь и агент создают собственные статусы, типы задач и
  резолюции, а не выбирают из зашитого списка. Системный набор — лишь начальные данные.
- Область справочника: глобальный (доступен всем очередям) или локальный для очереди —
  по той же логике, что и локальные поля в задаче 04.
- Модель `Queue`: ключ, название, описание, владелец, счётчик номеров задач, тип задачи по
  умолчанию, статус по умолчанию.
- Привязка типов задач к очереди: какие типы разрешены в этой очереди.
- Сценарии: создать очередь, изменить настройки, получить конфигурацию очереди целиком
  (типы, статусы, воркфлоу-заглушка, поля), архивировать очередь.
- Сценарии справочников: создать статус, тип, резолюцию; изменить название; отключить.
- Эндпоинты для очередей и справочников.
- Начальный набор справочников: типы (задача, баг, эпик), статусы (открыт, в работе, закрыт),
  резолюции (сделано, отклонено, дубликат).

## Что учесть

- Категория статуса — не украшение. Доски, прогресс проектов и правила автоматики опираются
  именно на неё, чтобы переименование статуса ничего не ломало. Категория обязательна и не
  может быть пустой.
- Счётчик номеров задач должен выдавать номера без дыр и без гонок при параллельных запросах.
  Продумать это здесь, а не в задаче про создание задач: там уже будет поздно.
- Ключ очереди неизменяем после создания — на нём построены ключи задач.
- Статус, в котором стоят задачи, нельзя просто удалить: либо запрет удаления непустого статуса,
  либо удаление с обязательным указанием статуса-замены и переносом задач. Выбрать первый
  вариант плюс явный сценарий переноса — «тихое» удаление оставит задачи со ссылкой в никуда
  и сломает доски и прогресс проектов.
- Категория задаётся при создании статуса и не меняется, если в статусе есть задачи: смена
  категории на лету переопределяет смысл «задача закрыта» задним числом.
- Удаление очереди с задачами запрещено; вместо удаления — архивация.
- Эндпоинт «конфигурация очереди целиком» будет основным источником данных для формы создания
  задачи во фронте, поэтому он должен отдавать всё нужное одним запросом.

## Готово, когда

- Очередь создаётся, отдаёт свою конфигурацию, архивируется.
- Собственные статусы, типы и резолюции создаются и подключаются к очереди.
- Удаление статуса с задачами отклоняется; перенос задач в другой статус работает.
- Параллельное выделение номеров задач не выдаёт дубликатов (тест на конкурентность).
- Тесты на сценарии и эндпоинты.

## Не входит

Воркфлоу-переходы (задача 07), локальные поля (задача 04).
