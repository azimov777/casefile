# 28. MCP-сервер: инструменты рабочего цикла, наборы токена, промпт и инструкции

## Цель

Дать агенту доступ ко всему циклу через MCP: инструменты по концепции, список которых
зависит от набора токена, промпт с дисциплиной и выжимка в инструкциях сервера. После
задачи агент в Claude Code берёт задачу, ведёт дело и закрывает её, не касаясь REST.

## Контекст

- `CONCEPT.md`, разделы 5.2 и 5.3; словарь идентификаторов в 7.
- Каркас MCP остался после задачи 20: `runtime`, `headers_middleware` с токеном
  в контекстной переменной, разведённый перевод ошибок. Обязательно прочитать `notes/mcp.md`:
  SDK 2.x, версии протокола, объект `changes` для частичных изменений, один инструмент
  на одно действие, ошибки инструментов и ресурсов.
- Текст скила: `skill/tracker-agent/SKILL.md`. Промпт отдаёт файл целиком, `instructions`
  берёт раздел «Кратко». Имена инструментов в скиле и в сервере обязаны совпадать.
- Сервисы для всех инструментов сделаны в задачах 21–27; здесь только тонкий слой.

- Сценарии дела уже разложены по видам действий ровно так, как названы инструменты в
  `CONCEPT.md`, 5.2: `add_summary`, `ask`, `answer`, `add_verdict`, `add_entry`
  (`app/services/case.py`). Все они — тонкие обёртки над `append_entry`, и инструмент
  должен звать обёртку, а не собирать нагрузку сам (выявлено в задаче 23).
- `read_entries(key, nos, types, after_no, limit)` целиком лежит в
  `case.list_entries` с теми же именами фильтров (выявлено в задаче 23).
- `link` и `unlink` зовут `links.add_link` / `links.remove_link`
  (`app/services/links.py`). Обе принимают **объекты обеих задач**, а не ключи: модуль
  связей намеренно не импортирует сценарии задач, иначе зависимость стала бы кольцевой.
  Инструмент разрешает оба ключа через `tasks.get_task` сам — ровно как это делает
  роутер (выявлено в задаче 24).
- Вид связи в аргументе называет роль задачи из `key`, а не второй стороны: `link(key:
  "TRK-1", kind: "blocks", other: "TRK-7")` — это «TRK-1 блокирует TRK-7». Описание
  аргумента обязано говорить это прямо: обратное соглашение выглядит так же и означает
  противоположное, а ошибка проявится не отказом, а задачей, взятой в работу поверх
  открытого блокера (выявлено в задаче 24).

## Ограничения

- Инструменты набора `task`: `get_task`, `read_entries`, `search_tasks`, `create_task`,
  `update_task`, `transition`, `add_summary`, `add_entry`, `ask`, `answer`, `add_verdict`,
  `link`, `unlink`, `get_queue`, `list_participants`, `wait_journal`. Набор `main` добавляет
  `create_queue`, `update_queue`, `register_participant`, `update_participant`.
  Выпуск токенов через MCP не делается.
- `tools/list` отдаёт только инструменты набора токена; вызов недоступного инструмента
  отклоняется той же ошибкой, что и в REST.
- Один инструмент это один вид действия. Составных инструментов нет.
- `add_entry` принимает только `decision`, `attempt`, `finding`, `artifact`, `note`;
  структурные записи идут через свои инструменты.
- Результат инструмента это данные, без подсказок. Ошибка переводится в код и причину.
- Все создающие инструменты принимают `idempotency_key` и передают его в механизм
  задачи 27.
- Описания инструментов и аргументов на русском, короткие, несут дисциплину («подшить
  в дело то, что должен знать преемник»), а не пересказ схемы.

## Выход

- Инструменты, промпт `tracker-discipline`, `instructions` при инициализации, фильтрация
  по набору.
- Возвращённые настройки `TRACKER_MCP_PAGE_SIZE` и `TRACKER_MCP_TEXT_LIMIT` — в
  `app/core/config.py` и в `.env.example` одной правкой с кодом, который их читает. Они
  удалены задачей 20 вместе с прежними инструментами: настройка без потребителя — это
  обещание, которого установка не выполняет (выявлено в задаче 20).
- README: раздел о подключении MCP-сервера к Claude Code с примером и о выпуске токена
  агенту.
- Тесты каждого инструмента через клиент SDK, тест на состав `tools/list` по наборам,
  тест соответствия имён инструментов именам в `SKILL.md`, заметки о неочевидном.

## Обзорные проверки

1. `tools/list` с токеном набора `task` содержит ровно шестнадцать перечисленных имён; с `main` ровно двадцать.
2. Вызов `create_queue` с токеном `task` отвечает ошибкой с кодом `permission_denied`.
3. `get_task` отдаёт тот же пакет преемника, что `GET /api/v1/tasks/{key}`, поле в поле; тест сравнивает.
4. `add_summary` с пустым `blockers` отвечает ошибкой с кодом валидации и именем поля.
5. `update_task` с `changes: {"tags": ["x"]}` не трогает исполнителя; с `changes: {"assignee": null}` снимает его.
6. `prompts/get tracker-discipline` возвращает текст, равный содержимому `SKILL.md`; `instructions` в ответе `initialize` равны разделу «Кратко».
7. `wait_journal(after, timeout=2)` без новых записей возвращается через две секунды с пустым списком.
8. Живая проверка: `claude mcp add` на поднятый контур, `get_task` по демонстрационной задаче отвечает; шаги описаны в README.
9. Тест на совпадение имён: каждый идентификатор `snake_case` в обратных кавычках в `SKILL.md`, за которым идёт открывающая скобка, существует как инструмент сервера; и каждый инструмент набора `task` упомянут в `SKILL.md` хотя бы раз.
10. Полный набор тестов зелёный; `docker ps` чист после работы.
