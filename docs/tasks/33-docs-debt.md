# 33. Документационный долг после сборки

## Цель

Довести документацию и мелочи конфигурации до правил `CONVENTIONS.md`, чтобы следующий
агент не спотыкался о неполные заметки, мёртвые настройки и следы старой модели в тестах.

## Контекст

Ревизия 2026-09-04 нашла:

- Пятнадцать записей в `notes/` без обязательного раздела «Как правильно:»
  (`CONVENTIONS.md`, раздел «Заметки»): в `notes/tasks.md` пять («Запрет правки
  проверяется по факту запроса…», «Пустая проверка отвергается…», «`transitions`
  в пакете…», «Сводка считается от последнего входа…», «Замечания к полям собираются…»);
  в `notes/journal.md` четыре («Внутрипроцессного хаба…», «У ленты нет окна
  переподключения…», «Схема кадра собирается…», «`after` и `cursor`…»);
  в `notes/demo.md` одна («Полнота демо проверяется…»); в `notes/links.md` две
  («Связи задачи читаются целиком…», «Закрытие блокера снимает признак…»);
  в `notes/api.md` три («Токены — ресурс верхнего уровня…», «Ключ идемпотентности
  проверяется доменом…», «Сплошная проверка требует ключ…»).
- `app/core/config.py`: поля `host` и `port` (`TRACKER_HOST`, `TRACKER_PORT`)
  приложением не читаются, адрес и порт uvicorn заданы в командах Compose.
- `tests/test_errors.py` и `tests/test_response_envelope.py` используют примеры
  `IssueNotFound`, `Issue` с текстами «Issue TRK-123 not found»: следы старой модели
  в единственном месте, где grep их ещё находит.
- `.env.example` уже дополнен переменными пула соединений вручную; нет проверки, что
  каждое поле настроек в нём описано.

## Ограничения

- Заметки только дополняются: существующие поля записей не переписывать.
- Удаление мёртвых настроек не должно менять команды Compose и README; если `TRACKER_PORT`
  используется в `docker-compose.yml` для проброса порта, оставить его там и описать
  в `.env.example` именно как переменную Compose, а из `Settings` убрать.

## Выход

- Все пятнадцать записей с разделом «Как правильно:».
- `Settings` без неиспользуемых полей; `.env.example` описывает каждое поле `Settings`
  и переменные Compose; тест, который сверяет поля `Settings` с `.env.example`.
- Тесты-примеры переименованы на нейтральные или на домен `Task`.

## Обзорные проверки

1. Скрипт по `docs/notes/*.md`: у каждой записи (заголовок `##`) есть все четыре поля «Что», «Почему важно», «Как правильно», «Где»; исключений нет.
2. `grep -rniE 'issue' app/ tests/ README.md skill/ docs/*.md` находит только `.gitignore`-подобные случайные совпадения или ничего.
3. Тест сверки `Settings` и `.env.example` зелёный; удалённые поля не встречаются ни в коде, ни в Compose, ни в README.
4. Полный набор тестов зелёный; `docker ps` чист после работы.
