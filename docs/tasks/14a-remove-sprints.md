# 14a. Убрать спринты

- **Блок:** Доски
- **Зависимости:** нет (выполняется до 15, 16 и 17)
- **Результат:** в продукте нет сущности «спринт»; доски и планирование живут без неё

## Зачем

Решение владельца: спринты продукту не нужны. Они были реализованы в задаче 11 вместе с
досками, и чем дольше они остаются в коде, тем дороже их убирать: задачи 15, 16 и 17
опишут их в вебхуках, в инструментах MCP и в публичном контракте, и удалять придётся уже
из четырёх мест вместо одного.

Убрать надо **до** этих задач, а не после (выявлено в задаче 14).

## Объём

- Удалить модель `Sprint` и колонку `issues.sprint_id` вместе с их индексами; миграция —
  отдельной ревизией, `downgrade` возвращает схему.
- Убрать сценарии спринтов из `app/services/boards.py`: создание, запуск, завершение с
  переносом незакрытых, удаление, состав.
- Убрать роутер `app/api/routes/sprints.py` и его схемы; снять подключение из
  `app/api/router.py`.
- Убрать поле `sprint` из единой точки изменения задачи (`IssueChanges`, `IssueField`),
  из снимка задачи в событии (`issue_snapshot`) и из ответов API.
- Убрать из языка запросов поле `sprint` и функцию `current` в его значении, если она
  обслуживает только спринт (`app/domain/query_language.py`, `app/services/search.py`).
- Убрать типы событий `sprint.*` и действия `sprint.*` из `app/domain/events.py`
  (`EventType`, `ACTION_EVENTS`) и `issue.set_sprint` оттуда же.
- Убрать `ObjectType.SPRINT`, ветку спринта в тексте уведомления
  (`app/domain/notifications.py`, `_describe_sprint`) и фикстуру `make_sprint`.
- Удалить тесты спринтов и части чужих тестов, которые их используют.
- Вычистить упоминания из `README.md`, `docs/CONCEPT.md`, `docs/notes/boards.md` и карт
  `AGENTS.md`.

## Что учесть

- **Событий `sprint.*` в outbox уже могло накопиться.** Тип события — строка, а не
  перечисление с CHECK, поэтому старые строки удаление члена `EventType` не сломает. Но
  подписчик уведомлений на неизвестном типе обязан отдавать пустую аудиторию и текст с
  именем типа, а не падать: это уже так (`audience_of`, `_describe_unknown`), и ломать
  это поведение при чистке нельзя (выявлено в задаче 14).
- **Уведомления и журнал срабатываний ссылаются на задачи, а не на спринты**, поэтому
  каскадов из-за удаления таблицы не будет. Проверить это глазами до миграции, а не
  после: `\d sprints` покажет входящие внешние ключи.
- Удаление колонки `issues.sprint_id` — необратимая потеря данных. Если в установке уже
  есть спринты, миграция обязана быть отдельным шагом, о котором сказано в README.

## Готово, когда

- В коде, схеме БД, API и документации нет слова «спринт».
- Весь набор тестов зелёный, контур поднимается с нуля.
- `alembic check` показывает только известные ложные срабатывания по CHECK перечислений.

## Не входит

Замена спринтов другой механикой планирования: задача только убирает.
