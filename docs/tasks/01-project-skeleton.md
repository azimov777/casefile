# 01. Каркас проекта и инфраструктура

- **Блок:** Каркас
- **Зависимости:** нет
- **Результат:** пустой, но работающий скелет, на который ложатся все остальные задачи

## Зачем

Все последующие задачи пишут код в одну и ту же структуру и опираются на одни и те же
механизмы: конфиг, подключение к БД, миграции, тесты. Если этого нет — каждый следующий агент
изобретёт своё, и проект развалится на несовместимые куски.

## Объём

- Структура пакетов по `CONVENTIONS.md` (`app/api`, `app/mcp`, `app/domain`, `app/services`,
  `app/db`, `app/automation`, `app/core`).
- Конфигурация через переменные окружения с валидацией (Pydantic Settings): адрес БД, режим
  отладки, параметры сервера. Пример `.env.example`.
- Асинхронное подключение к PostgreSQL, фабрика сессий, зависимость для получения сессии в запросе.
- Alembic: инициализация, автогенерация, первая пустая ревизия.
- `docker-compose.yml` с PostgreSQL для локальной разработки.
- Приложение FastAPI: подключение роутеров, единый обработчик ошибок в формате из соглашений,
  эндпоинт проверки здоровья, CORS.
- Базовый класс моделей SQLAlchemy с `id` (UUID), `created_at`, `updated_at`.
- Инфраструктура тестов: pytest, асинхронный клиент, фикстура сессии БД с откатом транзакции
  после теста, тестовая база.
- Управление зависимостями (`pyproject.toml`), линтер и форматтер.
- `README.md` с инструкцией запуска: поднять БД, применить миграции, запустить сервер, прогнать тесты.

## Что учесть

- Существующий `main.py` — заглушка от шаблона PyCharm. Его нужно заменить точкой входа проекта,
  а не пристраивать вокруг.
- Фикстура тестовой БД должна откатывать состояние между тестами, иначе тесты начнут зависеть от
  порядка выполнения — это выяснится через десять задач и будет дорого чинить.
- Единый обработчик ошибок должен уметь превращать доменные исключения в ответы с кодами ошибок.
  Сами доменные исключения появятся позже, но базовый класс исключения и механизм маппинга нужно
  заложить сейчас.
- Не заводить ORM-модели предметной области — это работа следующих задач.

## Готово, когда

- `docker compose up` поднимает БД, `alembic upgrade head` проходит, сервер стартует.
- Эндпоинт здоровья отвечает и подтверждает живое соединение с БД.
- `pytest` проходит на пустом наборе тестов плюс smoke-тест здоровья.
- В корне и в `app/` есть `AGENTS.md`.
