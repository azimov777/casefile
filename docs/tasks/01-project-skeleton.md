# 01. Каркас проекта и инфраструктура

- **Блок:** Каркас
- **Зависимости:** нет
- **Результат:** пустой, но работающий скелет, на который ложатся все остальные задачи

## Зачем

Все последующие задачи пишут код в одну и ту же структуру и опираются на одни и те же
механизмы: конфиг, подключение к БД, миграции, тесты. Если этого нет — каждый следующий агент
изобретёт своё, и проект развалится на несовместимые куски.

## Объём

- Структура пакетов по `CONVENTIONS.md` (`app/api`, `app/mcp`, `app/domain`, `app/services`,
  `app/db`, `app/automation`, `app/core`).
- Конфигурация через переменные окружения с валидацией (Pydantic Settings): адрес БД, режим
  отладки, параметры сервера. Пример `.env.example`.
- Асинхронное подключение к PostgreSQL, фабрика сессий, зависимость для получения сессии в запросе.
- Alembic: инициализация, автогенерация, первая пустая ревизия.
- **Docker как единственная среда запуска** (сквозное требование проекта):
  - `docker/Dockerfile.dev` — образ для разработки: dev-зависимости, автоперезапуск,
    исходники монтируются томом;
  - `docker/Dockerfile.prod` — образ для продакшена: многостадийная сборка, только рантайм-
    зависимости, код внутри образа, непривилегированный пользователь;
  - `docker-compose.yml` — контур разработки: приложение, PostgreSQL, именованный том данных,
    проверки здоровья, запуск приложения после готовности БД;
  - `docker-compose.prod.yml` — продакшен-контур на том же наборе сервисов;
  - `.dockerignore`;
  - отдельная команда (или сервис) для применения миграций и отдельная — для запуска тестов.
- Приложение FastAPI: подключение роутеров, единый обработчик ошибок в формате из соглашений,
  эндпоинт проверки здоровья, CORS.
- Базовый класс моделей SQLAlchemy с `id` (UUID), `created_at`, `updated_at`.
- Инфраструктура тестов: pytest, асинхронный клиент, фикстура сессии БД с откатом транзакции
  после теста, тестовая база.
- Управление зависимостями (`pyproject.toml`), линтер и форматтер.
- `README.md` с инструкцией запуска **только через Docker**: поднять контур, применить миграции,
  запустить сервер, прогнать тесты, посмотреть логи. Плюс раздел о различиях дев- и прод-контуров.

## Что учесть

- Существующий `main.py` — заглушка от шаблона PyCharm. Его нужно заменить точкой входа проекта,
  а не пристраивать вокруг.
- Фикстура тестовой БД должна откатывать состояние между тестами, иначе тесты начнут зависеть от
  порядка выполнения — это выяснится через десять задач и будет дорого чинить.
- Единый обработчик ошибок должен уметь превращать доменные исключения в ответы с кодами ошибок.
  Сами доменные исключения появятся позже, но базовый класс исключения и механизм маппинга нужно
  заложить сейчас.
- Не заводить ORM-модели предметной области — это работа следующих задач.
- Дев-образ обязан давать быструю обратную связь: правка файла подхватывается без пересборки
  образа. Если для проверки изменения нужно пересобирать образ, дев-контур сделан неправильно.
- Прод-образ собирается многостадийно: компиляторы и заголовки остаются в стадии сборки.
  Разница в размере между дев- и прод-образом должна быть заметной — это признак, что
  многостадийность работает.
- Зависимости устанавливаются отдельным слоем до копирования кода, иначе каждая правка исходника
  будет заново тянуть все пакеты.
- Приложение конфигурируется только переменными окружения: один и тот же образ должен работать
  и в дев-, и в прод-контуре без пересборки.
- Миграции — явный шаг, а не автозапуск при старте приложения. Три реплики, одновременно
  применяющие миграции, — это гонка и испорченная схема.

## Готово, когда

- `docker compose up` поднимает весь дев-контур одной командой; миграции применяются командой
  из README; сервер стартует.
- Прод-контур собирается и запускается из `docker-compose.prod.yml`, образ не содержит
  dev-зависимостей и работает от непривилегированного пользователя.
- Правка исходника в дев-контуре подхватывается без пересборки образа.
- Эндпоинт здоровья отвечает и подтверждает живое соединение с БД.
- Тесты запускаются в контейнере одной командой и проходят.
- В корне и в `app/` есть `AGENTS.md`.
