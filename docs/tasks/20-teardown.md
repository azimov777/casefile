# 20. Снос старого доменного слоя

## Цель

Оставить от системы фундамент, на котором строится трекер для агентов, и убрать весь
старый домен целиком. После задачи контур поднимается с нуля, тесты зелёные, а в коде нет
ни одной механики из списка «уходит» в `SCOPE.md`. Следующие задачи строят новое на чистом
месте, а не рядом с мёртвым кодом.

## Контекст

- Новая модель: `CONCEPT.md`. Судьба каждой старой возможности: `SCOPE.md`. Старый код
  целиком доступен в git по коммиту `49e2e49`; всё, что удаляется здесь, при необходимости
  берётся оттуда следующими задачами.
- **Остаётся**: `app/core` (конфиг, зависимости, логирование, `sentinels`), основа `app/db`
  (движок, сессии, `get_session` и `session_scope`, базовая модель, настройка Alembic),
  акторы и токены с аутентификацией (переделываются в задаче 21, здесь не трогать),
  оболочка ответа и обработчики ошибок, `app/api/contract.py` с `ENVELOPE_EXEMPT`
  и сплошная проверка оболочки, `/health`, выгрузка OpenAPI и её проверка, каркас
  MCP-сервера (`runtime`, `headers_middleware`, перевод ошибок), инфраструктура тестов,
  оба образа Docker и оба контура Compose.
- **Уходит**: задачи, очереди (пересоздаются в 21 на новой модели; счётчик номеров
  переносится оттуда же), типы и статусы, справочники, резолюции, реестр полей, воркфлоу,
  связи, комментарии, чеклисты, теги, проекты, портфели, доски, спринты, наблюдатели,
  журнал изменений, outbox, воркер, реестр подписчиков, срок хранения, уведомления,
  инбокс, подписки, вебхуки, SSE, поиск и язык запросов, сохранённые фильтры, автоматика
  с планировщиком, все инструменты, ресурсы и нотификации MCP, демо-данные, агрегаты.
- Заметки `notes/` по удалённым областям остаются как история: их не удаляют.
- Данных, которые нужно сохранить, нет: цепочка миграций начинается заново.

## Ограничения

- Не вырезать по кусочку: модуль удаляется целиком со своими таблицами, схемами,
  маршрутами, инструментами и тестами. Оставшийся код не должен импортировать удалённое.
- Не переделывать оставшееся под новую модель: это задачи 21–29. Здесь только удаление
  и минимальная правка, чтобы всё собиралось и поднималось.
- Миграции: удалить все ревизии и создать одну начальную, которая создаёт только
  оставшиеся таблицы (акторы, токены). Никаких `DROP` старых таблиц в ней: контур
  поднимается с нуля.
- MCP-сервер должен стартовать с пустым списком инструментов и отвечать на `initialize`.
- README: удалить разделы про ушедшие механики, чтобы он не лгал; полная переработка
  в задаче 29.
- Compose: убрать сервисы воркера и планировщика из обоих контуров.

## Выход

- `app/` без модулей удалённых областей; `app/automation/` нет.
- Одна ревизия Alembic.
- Оба контура Compose с сервисами: БД, HTTP-сервер, MCP-сервер, шаг миграций.
- Тесты удалённых областей удалены; оставшийся набор зелёный.
- `README.md` без разделов про удалённое; `AGENTS.md` всех затронутых папок обновлены.
- Заметка в `notes/` о том, что и почему оставлено (например, `teardown.md`): какие
  модули признаны фундаментом и на что в них опираться.

## Обзорные проверки

1. `grep -rniE 'workflow|sprint|board|project|portfolio|comment|checklist|automation|webhook|notification|inbox|watcher|resolution|saved_filter|custom_field|outbox' app/` не находит ничего, кроме, возможно, слова `project` в конфиге Compose или названии пакета.
2. `ls app/db/migrations/versions` (или путь, где лежат ревизии) содержит ровно один файл.
3. Контур разработки поднимается с нуля без старого тома, миграции применяются, `/health` отвечает `200`.
4. `docker compose config --services` в обоих контурах показывает БД, HTTP-сервер, MCP-сервер и шаг миграций; воркера и планировщика нет.
5. Полный набор тестов в контейнере зелёный.
6. Команда выгрузки OpenAPI отрабатывает; в схеме нет маршрутов ушедших областей, есть `/health` и маршруты акторов и токенов.
7. MCP-сервер отвечает на `initialize` и отдаёт пустой `tools/list`.
8. `grep -niE 'спринт|доск|проект|коммент|чеклист|автоматик|вебхук|инбокс' README.md` не находит описаний удалённых механик.
9. `docker ps` после работы не показывает контейнеров задачи.
