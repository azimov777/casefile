# 35. Чистка документации после переписывания

**Ожидает решения владельца.** Задача нарушает правило «заметки только копятся»
из `CONVENTIONS.md`: удаляет и переносит записи о снесённой механике. Брать только
после явного согласия; при отказе удалить файл задачи.

## Цель

Оставить в документации только то, что описывает существующий код, и исторические
записи, у которых есть живой смысл. Новый агент читает заметки по своей области
до начала работы; сейчас часть из них ведёт в удалённый код без пометки.

## Контекст

Ревизия 2026-09-04 по всем файлам `docs/`, README и картам. Проверены ссылки «Где:»
каждой записи заметок на существование файлов и символов.

- **Устарели целиком**: `notes/retention.md`, `boards.md`, `comments.md`, `automation.md`,
  `notifications.md`, `workflow.md`. Все «Где:» мертвы; переиспользуемые приёмы уже
  переоткрыты в `journal.md`, `mcp.md`, `db.md`, `search.md`. Единственная невосполнимая
  запись: `comments.md` про границы regex для упоминаний.
- **Оставить**: `notes/webhooks.md`. Возврат вебхуков назван возможным в `ROADMAP.md`,
  материал про подпись и повторы доставки больше нигде не сохранён.
- **Хвосты «Прежняя модель»**: `notes/search.md` (со строки «Прежняя модель поиска»
  до конца), `notes/links.md` (с разделителя до конца). В `links.md` две части хвоста
  описывают текущее поведение и должны переехать в актуальную часть: отсутствие каскада
  при снятии связей и техника защиты от циклов, на которую ссылается
  `app/db/repositories/links.py` (имена обновить на `reaches`, `MAX_LINK_DEPTH`).
- **Мёртвые записи без баннера** вперемешку с живыми: `notes/api.md` (около половины
  записей ссылаются на `routes/actors.py`, `catalogs.py`, `issues.py`, `events.py`,
  `webhooks.py`, `refs.py`, `projects.py`, `workflows.py`, `aggregates.py`), `notes/db.md`
  (модели `catalog`, `field`, `issue`, `saved_filter`, `comment`, `project`, `board`,
  старые ревизии; запись про `clock_timestamp()` описывает решение, которого больше нет),
  `notes/mcp.md` (`push.py`, `resources.py`, `tools/issues.py`, `tools/setup.py`; «Где:»
  про частичные изменения должно указывать на `app/mcp/arguments.py`, `TaskChanges`),
  `notes/python.md` (три «Где:» на удалённые файлы при верных уроках), `notes/docker.md`
  (записи про `worker.py`, `scheduler.py`, `schema_is_missing`), `notes/testing.md`

  `test_aggregates_api.py`).
- **`notes/teardown.md`** написан в будущем времени про задачи 25–28 и утверждает, что
  `tools/list` пуст и задача 28 не сделана.
- **`docs/SCOPE.md`**: инвентарь старого объёма, роль исчерпана; содержание свёрнуто
  в `CONCEPT.md`, раздел 6, и `ROADMAP.md`. Ссылки на него: `ROADMAP.md`, `docs/AGENTS.md`,

- **Повторы**: README описывает `bootstrap` дважды, ожидание на LISTEN/NOTIFY трижды,
  состав сервисов дважды; `FRONTEND.md` повторяет README в разделах про аутентификацию,

  живой раздел один: «Что откладывается до наблюдений».

## Ограничения

- Живые записи не переписывать; правятся только мёртвые ссылки «Где:» и удаляются
  мёртвые записи. Перед удалением записи убедиться, что её урок есть в живой части
  или не имеет смысла для нового кода.
- Пути и коды в `FRONTEND.md` не трогать: их стережёт тест.
- `ERRORS.md` и `openapi.json` не редактировать руками.
- Правило «заметки только копятся» после чистки переформулировать в `CONVENTIONS.md`:
  заметки не чистятся, пока жив код, который они описывают; при сносе механики
  её заметки удаляются вместе с кодом.

## Выход

- Удалены шесть устаревших файлов заметок (запись про regex упоминаний перенесена
  в `python.md`), хвосты «Прежняя модель» в `search.md` и `links.md` (с переносом двух
  живых частей), `SCOPE.md` со всеми ссылками на него.
- Мёртвые записи вычищены или помечены в `api.md`, `db.md`, `mcp.md`, `python.md`,
  `docker.md`, `testing.md`; `teardown.md` переведён в прошедшее время и говорит правду
  о задаче 28.
- README без повторов; `FRONTEND.md` ссылается на README вместо пересказа; `ROADMAP.md`
  свёрнут: абзац истории плюс «Что откладывается до наблюдений».
- Карты `AGENTS.md` папок `docs` и `docs/notes` актуальны; `CONVENTIONS.md` с новым
  правилом про заметки; тест формата заметок зелёный.

1. Скрипт по всем «Где:» в `docs/notes/*.md`: каждый упомянутый файл существует, каждый упомянутый символ находится grep в этом файле; исключений нет.

3. `grep -c 'LISTEN' README.md` не больше одного раздела; `bootstrap` описан в README один раз.
4. `tests/test_artifacts.py` и тест формата заметок зелёные; полный набор тестов зелёный.
5. Карта `docs/notes/AGENTS.md` перечисляет ровно существующие файлы.
6. `docker ps` чист после работы.
