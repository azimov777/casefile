# 30. Надёжность: гонки переходов и связей, чужие исключения вне REST, отмена ожидания

## Цель

Закрыть три дыры, найденные ревизией 2026-09-04 после сборки: переход читает факты
без блокировки и может разойтись с параллельной постановкой связи; нарушение уникальности
вне REST (в MCP и CLI) улетает сырым `IntegrityError`; долгий опрос ленты не отменяется,
когда клиент ушёл. Контракт API и MCP не меняется.

## Контекст

- `CONCEPT.md`, 3.3 (валидации переходов), 3.5 (связи закрытой задачи не меняются),
  4.1 (лента). Заметки `notes/journal.md` (очередь на подшивку), `notes/tasks.md` (точки
  подключения проверок), `notes/db.md` (оптимистичная блокировка), `notes/testing.md`
  (проверка гонок).
- **Гонка фактов.** `app/services/tasks.py`, `_transition_facts` читает блокеры, детей
  и вердикты обычным `SELECT`, а фиксация защищена только `version` самой задачи
  (`_flush_checking_version`). Постановка связи `blocked_by` или рождение ребёнка
  не меняют `version` переводимой задачи, поэтому сценарий «T1 прочитала факты, T2
  добавила ребёнка и зафиксировалась, T1 закрыла родителя в `done`» проходит:
  закрытый родитель с открытым ребёнком, и при этом T2 успела проверить, что родитель
  ещё не закрыт. Симметрично для `blocked_by` и входа в `in_progress`.
  Подшивка записи уже берёт глобальную `pg_advisory_xact_lock`
  (`app/db/repositories/entries.py`) и держит её до конца транзакции; но берётся она
  в конце сценария, когда факты уже прочитаны.
- **Чужие исключения.** `app/services/queues.py` и другие создающие сценарии работают
  по схеме «проверить, потом вставить», полагаясь на уникальность в базе. В REST
  `IntegrityError` переводится глобальным обработчиком (`app/api/errors.py`) в `409`.
  В MCP (`app/mcp/runtime.py` ловит только `AppError`) и в CLI (`session_scope`
  в `app/db/session.py` откатывает и пробрасывает) перевода нет.
- **Отмена ожидания.** `GET /api/v1/journal?wait=N` (`app/api/routes/journal.py`,
  `app/services/journal.py`) не получает `Request` и не проверяет
  `is_disconnected()`; после ухода клиента корутина доигрывает до `wait`. Поток
  `journal/stream` отменяется сам через `StreamingResponse`.

## Ограничения

- Никакой автоматики, никаких новых фоновых процессов.
- Не менять оболочку ответов, коды существующих ошибок и схемы OpenAPI; новые коды
  (если появятся) идут через общий реестр и попадают в `ERRORS.md` командой.
- Рекомендуемый путь для гонки фактов: захватывать очередь на подшивку
  (`pg_advisory_xact_lock`) **в начале** каждого мутирующего сценария, до чтения фактов,
  а не в момент подшивки. Это не добавляет блокировок сверх уже существующих: сценарий
  и так держит её до конца транзакции. Альтернатива с `SELECT ... FOR UPDATE` по строкам
  задачи, блокеров и детей допустима, но тогда порядок захвата должен быть единым
  во всех сценариях, иначе появится взаимная блокировка.
- Перевод `IntegrityError` в доменную ошибку делать в одном месте, общем для REST, MCP
  и CLI, а не тремя копиями.

## Выход

- Мутирующие сценарии (переход, правка, постановка и снятие связи, создание задачи
  с родителем, подшивка записи) читают факты уже под блокировкой; заметка в `notes/`
  о порядке захвата.
- Общий перевод `IntegrityError` в доменную ошибку с кодом, который видят REST, MCP и CLI
  одинаково; сценарии создания очереди, участника, токена, связи и записи опираются
  на него.
- Долгий опрос ленты прекращается при уходе клиента не позже одного интервала опроса.
- Тесты на каждую из трёх дыр, `ERRORS.md` обновлён, если добавлен код.

## Обзорные проверки

1. Тест на гонку по схеме из `notes/testing.md`: транзакция A начинает переход родителя в `done` и останавливается после чтения фактов; транзакция B ставит связь `parent` на новый ребёнок. После завершения обеих ровно один исход: либо B получила `task_closed`, либо A получила отказ по незакрытым детям. Состояние «родитель в `done` и открытый ребёнок» не воспроизводится.
2. Тот же тест для `blocked_by` и входа в `in_progress`: если связь зафиксирована раньше перехода, переход отвечает `task_blocked`; состояние «`status_changed` в `in_progress` с большим `seq`, чем `link_added` на открытый блокер» не воспроизводится.
3. Два параллельных `create_queue` с одним ключом через клиент MCP: один создаёт, второй получает ошибку с доменным кодом; в логах MCP нет трассировки `IntegrityError`.
4. То же через CLI `issue-token`/`init` или другой создающий сценарий CLI: команда завершается с осмысленным сообщением и кодом выхода, а не трассировкой.
5. Тест ASGI: запрос `journal?wait=30` получает `http.disconnect` через секунду; серверная корутина завершается не позже `journal_wait_poll_interval` после этого, что проверяется по времени или по счётчику активных ожиданий.
6. Полный набор тестов зелёный; контур поднимается с нуля; `docker ps` чист после работы.
