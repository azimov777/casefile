# 12. Поиск, фильтры, язык запросов

- **Блок:** Поиск
- **Зависимости:** 05, 04
- **Результат:** задачи ищутся строкой запроса и структурным фильтром

## Зачем

Поиск — то, чем агент и фронт пользуются чаще всего. Для агента особенно важен текстовый язык:
одна строка вместо конструирования сложного тела запроса, и её же можно сохранить, передать,
положить в правило автоматики.

## Объём

- Внутреннее представление фильтра: условия по системным полям, по кастомным полям, логические
  операторы, сортировка.
- Структурный поиск: параметры запроса (очередь, статус, категория статуса, тип, исполнитель,
  автор, наблюдатель, теги, проект, спринт, диапазоны дат, значения кастомных полей),
  сортировка, курсорная пагинация, выбор возвращаемых полей.
- Язык запросов: разбор строки вида
  `queue: TRK and status: open and assignee: me() and deadline: <= today()` в то же внутреннее
  представление.
- Операторы: равно, не равно, входит в список, больше/меньше, пусто/не пусто, содержит.
- Функции: `me()`, `today()`, `now()`, относительные даты (`today() - 7d`), `empty()`.
- Адресация локальных полей через префикс очереди (`TRK.severity: critical`).
- Полнотекстовый поиск по названию, описанию и комментариям. У мягко удалённого комментария
  текст затёрт, поэтому исключать его из индекса отдельным условием не нужно
  (выявлено в задаче 09).
- Сохранённые фильтры: имя, строка запроса или структурный фильтр, владелец.
- Эндпоинты поиска и сохранённых фильтров.

- Словарь существующих тегов уже есть — `GET /api/v1/tags` с алфавитной курсорной страницей
  и числом задач (`app/services/tags.py`). Фильтр по тегам опирается на него, а второй способ
  перечислять теги не заводится: два разных списка одних и тех же меток разойдутся регистром
  и фильтром (выявлено в задаче 09).

## Что учесть

- Язык запросов и структурный фильтр обязаны сходиться в **одном** внутреннем представлении,
  из которого строится SQL. Две независимые реализации разойдутся по поведению, и агент со
  фронтом получат разные результаты на одинаковый по смыслу запрос.
- Ошибка разбора запроса должна указывать позицию и причину: агент будет исправлять запрос по
  этому сообщению, и «invalid query» отправит его в слепой перебор.
- Кастомные поля фильтруются по JSONB — проверить, что запросы используют GIN-индекс, а не
  последовательное сканирование. Это стоит проверить на объёме хотя бы в десятки тысяч задач.
  Ключ в `values` — это **ссылка** на поле (`TRK.severity`), а не ключ; формат значения по
  каждому типу — в докстринге `app/domain/fields.py` (выявлено в задаче 04).
- **Разрешение имени в поле — отдельная функция, общая с реестром.** Имя из запроса сначала
  сверяется со списком системных полей (`SYSTEM_FIELD_KEYS` в `app/domain/fields.py`) и
  разрешается в колонку, и только потом ищется в реестре полей. Реестр уже не даёт завести
  кастомное поле с ключом системного, поэтому пересечения быть не может — но порядок
  проверки должен быть явным, иначе `status` однажды начнёт искаться в JSONB
  (выявлено в задаче 04).
- Значения дат в JSONB хранятся строками (`YYYY-MM-DD` и ISO 8601 в UTC), поэтому сравнение
  диапазонов по ним — лексикографическое либо через приведение типа. Формат подобран так,
  что лексикографический порядок совпадает с хронологическим; проверить это на границе
  часовых поясов (выявлено в задаче 04).
- Курсорная пагинация должна быть устойчивой: сортировка обязана включать уникальный тайбрейкер,
  иначе задачи будут дублироваться и пропадать между страницами.
- Выбор возвращаемых полей — не оптимизация, а требование: полная задача с историей в выдаче на
  сто позиций съест контекст агента целиком.
- Язык — не SQL. Не пытаться поддержать произвольную вложенность и подзапросы: набор операторов
  фиксированный, всё остальное отклоняется с понятной ошибкой.

## Готово, когда

- Одинаковые по смыслу структурный фильтр и строка запроса дают идентичный результат.
- Поддержаны все перечисленные операторы и функции, ошибки разбора внятные.
- Пагинация устойчива при параллельном изменении данных.
- Тесты: разбор языка (включая ошибки), фильтрация по каждому типу поля, пагинация.

## Не входит

Ранжирование по релевантности, поисковые подсказки.
