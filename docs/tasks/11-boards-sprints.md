# 11. Доски и спринты

- **Блок:** Доски
- **Зависимости:** 05, 07, 12 (желательно, но можно начать раньше)
- **Результат:** задачи раскладываются по колонкам и планируются по спринтам

## Зачем

Доска — основной рабочий экран фронтенда, спринт — единица планирования. Обе сущности требуют
собственного порядка задач, который не выводится ни из одного бизнес-поля.

## Объём

- Модель `Board`: название, источник задач (список очередей или сохранённый фильтр), настройки
  отображения.
- Модель `BoardColumn`: название, порядок, набор статусов, попадающих в колонку, лимит задач
  в работе (необязательный).
- Модель `Sprint`: название, доска, даты начала и окончания, состояние
  (планируется / активен / завершён), цель спринта.
- Принадлежность задачи спринту.
- Ранжирование: позиция задачи в бэклоге и внутри колонки, перемещение «поставить до/после
  задачи X».
- Сценарии: собрать доску (колонки с задачами), переместить задачу между колонками (через
  переход воркфлоу, а не прямой записью статуса), переупорядочить, начать спринт, завершить
  спринт с переносом незакрытых задач.
- Эндпоинты досок, колонок, спринтов, бэклога.

## Что учесть

- **Перемещение карточки между колонками — это переход воркфлоу.** Если писать статус напрямую,
  доска станет дырой в процессе: через неё можно будет обойти любые проверки из задачи 07.
- Ранжирование делать разреженными позициями (или строковыми ключами порядка), чтобы вставка
  между двумя карточками не переписывала таблицу. Предусмотреть периодическую перенумерацию
  при исчерпании промежутков.
- Сборка доски — самый нагруженный запрос всего API: одна доска может тянуть тысячи задач.
  Нужна пагинация внутри колонки и ограничение набора возвращаемых полей.
- Завершение спринта — сценарий с выбором: перенести незакрытые задачи в следующий спринт или
  в бэклог. Решение принимает вызывающий, а не система.
- Если задача 12 ещё не сделана, источник задач доски ограничить списком очередей, оставив
  место для фильтра.

## Готово, когда

- Доска собирается с задачами по колонкам, карточка перемещается с соблюдением воркфлоу.
- Порядок задач сохраняется и не ломается при вставках.
- Спринт запускается и завершается с переносом задач.
- Тесты на сборку доски, ранжирование, жизненный цикл спринта.
