# 29. Сборка: первый экран, демо-данные, OpenAPI, справочник ошибок, README

## Цель

Довести систему до состояния, в котором её можно отдать фронтенду и назначателю: первый
экран одним запросом, демо-данные, наполняющие каждый экран, выгруженная и проверенная
схема OpenAPI, собранный справочник ошибок и README, описывающий только то, что есть.

## Контекст

- `CONCEPT.md` целиком; `FRONTEND.md` описывает ожидаемый контракт и проверяется здесь
  на соответствие OpenAPI.
- Команда сборки `ERRORS.md` и выгрузка OpenAPI остались после задачи 20.
- README после задачи 20 урезан; здесь пишется заново под новую модель.

## Ограничения

- `GET /api/v1/bootstrap`: текущий участник, очереди, число открытых вопросов,
  адресованных ему. Ничего сверх этого.
- Демо-данные одной командой в Docker: очередь `DEMO` с описанием, задачи во всех шести
  статусах, дела с записями всех типов, включая открытый блокирующий вопрос, связи всех
  трёх видов, зарегистрированные человек и агент, задача с временной меткой автора.
  Команда идемпотентна: повторный запуск не плодит дубли.
- README: быстрый старт с нуля, первичная инициализация, демо, доступ к API, подключение
  MCP к Claude Code, тесты одной командой, переменные окружения. Никаких описаний
  механик, которых нет.

## Выход

- `bootstrap`, команда демо-данных, `openapi.json` в репозитории, актуальный `ERRORS.md`,
  переписанный `README.md`, `FRONTEND.md` сверен с OpenAPI и поправлен там, где разошёлся,
  карты `AGENTS.md` всех папок актуальны.
- Тесты сквозных сценариев: полный цикл задачи от создания до `done` через REST, тот же
  цикл через MCP, сценарий ожидания ответа на блокирующий вопрос из `CONCEPT.md` 4.6.

## Обзорные проверки

1. Выгрузка OpenAPI проходит; проверка находит ноль дублей `operation_id` и ноль маршрутов без модели ответа; `openapi.json` в репозитории равен выгруженному.
2. Каждый путь, упомянутый в `FRONTEND.md`, есть в `openapi.json`; проверяется скриптом или тестом.
3. Команда сборки `ERRORS.md` даёт файл, совпадающий с закоммиченным; каждый код, который бросает код приложения, есть в справочнике.
4. С нуля: поднять контур, применить миграции, инициализация печатает токен, демо наполняет базу; `GET /api/v1/bootstrap` с этим токеном отдаёт очередь `DEMO` и ненулевое число открытых вопросов.
5. Повторный запуск демо не меняет число задач и записей.
6. Сквозной тест REST: создать, открыть, взять, подшить решение и попытку, сводку, перевести в `review`, вердикты, `done`; в описи ровно ожидаемая последовательность типов.
7. Сквозной тест MCP повторяет тот же цикл инструментами и получает ту же опись.
8. Сквозной тест ожидания: задача в `in_progress` задаёт блокирующий вопрос, уходит в `open`; запрос кандидатов назначателя её не показывает; после ответа показывает; лента отдаёт `answer` по фильтру.
9. README воспроизводим: все команды из быстрого старта выполнены подряд на чистой машине с Docker и дали описанный результат.
10. Полный набор тестов зелёный; `docker ps` чист после работы.
