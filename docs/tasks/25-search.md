# 25. Поиск и список задач

## Цель

Дать назначателю, агенту и интерфейсу один способ отбирать задачи: структурный фильтр
и текстовый язык запросов над одними и теми же полями, включая вычисляемые признаки,
с курсорной пагинацией и выбором возвращаемых полей. После задачи запрос кандидатов
назначателя выражается одной строкой.

## Контекст

- `CONCEPT.md`, разделы 4.3 и 4.4; пример запроса назначателя в 4.3.
- Экранирование шаблона `LIKE` для поиска подстроки уже написано и лежит в `49e2e49`
  файлом `app/db/sql.py`; в текущем коде его нет, удалён задачей 20 как код без
  вызывающих (`notes/teardown.md`). Писать его заново по месту не надо: две копии
  расходятся молча (выявлено в задаче 20).
- Старый поиск (git `49e2e49`, заметки `notes/search.md`): одно представление на два
  входа, разбор языка с ошибкой в позиции, курсорная пагинация с устойчивой сортировкой,
  выбор полей. Переносить подход, поля другие.
- Вычисляемые признаки реализованы в задачах 23 и 24; здесь они становятся полями отбора.

## Ограничения

- Поля отбора: `queue`, `status`, `assignee`, `tags`, `priority`, `blocked`,
  `open_questions`, `open_blocking_questions`, `text` (подстрока в названии и описании).
  Функций дат, `me()` и сохранённых фильтров нет.
- Сортировка: по ключу, по времени обновления, по приоритету; направление явное; курсор
  устойчив при вставках.
- `fields` ограничивает ответ перечисленными полями плюс `key` всегда.
- Структурный фильтр и язык запросов дают одинаковый результат на одинаковых условиях
  и реализованы одним представлением.

## Выход

- `GET /api/v1/tasks` с параметрами `query`, структурными параметрами по каждому полю,
  `sort`, `fields`, `cursor`, `limit`.
- Разбор языка запросов с ошибкой, указывающей позицию и допустимые поля.
- Индексы под реальные запросы.
- Тесты, заметки о неочевидном.

## Обзорные проверки

1. `query=queue: TRK and status: open and blocked: false and open_blocking_questions: 0` отдаёт ровно те задачи, которые можно брать в работу; проверить на наборе с заблокированной задачей, с блокирующим вопросом и с обычной `open`.
2. Тот же отбор структурными параметрами даёт тот же список в том же порядке.
3. `query=status: opne` отвечает `422` с позицией ошибки и списком допустимых значений.
4. Между двумя страницами вставлена новая задача: вторая страница не содержит дублей и не теряет задач, которые были в выборке до вставки.
5. `fields=title,status` отдаёт только `key`, `title`, `status`.
6. `query=deadline: today` отвечает `422` с перечнем допустимых полей.
7. `tags: backend` находит задачу с несколькими тегами, среди которых `backend`.
8. Полный набор тестов зелёный; `docker ps` чист после работы.
