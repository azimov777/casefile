# 04. Реестр полей и значения

- **Блок:** Поля
- **Зависимости:** 01, 02, 03
- **Результат:** в задачу можно добавить произвольное поле без миграции

## Зачем

Разные процессы требуют разных атрибутов: у бага — серьёзность, у релиза — версия сборки.
Плодить колонки под каждый случай нельзя, поэтому нужен реестр полей и типизированное хранение
значений.

## Объём

- Модель `Field`: ключ, отображаемое название, тип значения, множественность, область действия
  (глобальное или локальное для конкретной очереди), обязательность, значения для перечислений,
  значение по умолчанию, порядок отображения.
- Типы значений минимум: строка, многострочный текст, число, дата, дата со временем, флаг,
  перечисление, ссылка на актора, ссылка на задачу.
- Валидатор: проверяет набор значений против набора полей, приводит типы, возвращает понятные
  ошибки с указанием поля.
- Сценарии: создать поле, изменить, получить поля, применимые к связке «очередь + тип задачи».
- Эндпоинты управления полями.
- Хранение значений в `values JSONB` с GIN-индексом (сама колонка появится в задаче 05 —
  здесь описать формат и договориться о нём).

## Что учесть

- Локальное поле адресуется с префиксом очереди (`TRK.severity`), глобальное — без префикса.
  Разрешение имени в поле — отдельная функция, ей будут пользоваться и поиск, и автоматика.
- Формат хранения значения в JSONB зафиксировать явно и описать в коде: как хранится дата, как
  множественное значение, как ссылка на актора. Все последующие задачи будут читать этот формат,
  и разночтения дадут молчаливые баги.
- Изменение типа существующего поля с данными — запрещено. Разрешено переименование и изменение
  обязательности.
- Удаление поля со значениями — только мягкое (пометка «скрыто»), иначе история изменений
  станет нечитаемой.
- Валидатор должен возвращать **все** ошибки сразу, а не первую: фронту нужно подсветить
  всю форму за один ответ.

## Готово, когда

- Поле создаётся, применимость к очереди и типу задачи вычисляется корректно.
- Валидатор принимает корректные значения и отвергает некорректные с внятными сообщениями.
- Тесты на каждый тип значения, на множественность, на обязательность.

## Не входит

Использование полей в фильтрах (задача 12).
