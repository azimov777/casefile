# 21. Удалить портфели

- **Блок:** Проекты
- **Зависимости:** нет
- **Результат:** портфелей нет, проекты работают самостоятельно

## Зачем

Портфель — уровень управленческой отчётности «продукт → отдел → направление». Наблюдение за
процессом человеку дают проекты и доски, а агентам портфель не даёт ничего.

## Объём

- Убрать сущность портфеля, вложенность портфелей, привязку проекта к портфелю, агрегированный
  прогресс по портфелю, проверку циклов вложенности.
- Убрать эндпоинты, инструменты MCP, поля в схемах, фильтры по портфелю.
- Миграция, удаляющая данные и колонку связи у проекта.
- Проекты, их состав, прогресс и связь задач с проектом **сохраняются**.
- Вычистить упоминания из документации, демо-данных и тестов.

## Что учесть при удалении

Общие ловушки — см. раздел «Что учесть при удалении» в задаче 20 (история изменений,
сохранённые фильтры и правила, необратимость миграции, хвосты в документации и MCP).

Специфика:

- Прогресс проекта считался сам по себе, портфель лишь агрегировал вложенное — убедиться, что
  удаление агрегации не задело расчёт прогресса проекта.
- Если подписки на уведомления умели указывать область «портфель», такие подписки надо
  мигрировать или удалить, а не оставить указывающими в пустоту.

## Готово, когда

- Портфелей нет ни в API, ни в MCP, ни в схеме БД, ни в документации.
- Проекты создаются, собирают задачи из разных очередей, прогресс считается.
- Весь набор тестов зелёный, живая проверка пройдена.
