# 27. Идемпотентность создающих вызовов

## Цель

Сделать повтор создающего запроса безопасным: агент, упавший до получения ответа,
повторяет вызов с тем же ключом и получает первый результат, а не дубль. После задачи
все создающие маршруты REST принимают `Idempotency-Key`, и тот же механизм готов для
аргумента `idempotency_key` в MCP.

## Контекст

- `CONCEPT.md`, раздел 4.5.
- Создающие вызовы: задача, запись дела любого типа, очередь, участник, токен.
  У выпуска токена особенность: повтор обязан вернуть тот же секрет, значит, хранится
  ответ целиком.
- Ключ живёт в паре с токеном: одинаковые ключи разных токенов независимы.

## Ограничения

- Хранится ключ, отпечаток тела, статус и тело ответа. Повтор с тем же ключом и тем же
  отпечатком возвращает сохранённый ответ; с другим отпечатком отвечает `409`.
- Одновременные повторы одного ключа не создают двух объектов: уникальность на уровне
  базы, а не проверка в коде.
- Срок жизни ключа (например, сутки) соблюдается без фонового процесса: устаревшие
  ключи удаляются попутно при записи нового.
- Без заголовка поведение обычное.
- Сервисный слой один для REST и MCP: задача 28 передаёт аргумент в тот же механизм.

## Выход

- Таблица ключей идемпотентности, сервис «выполнить один раз», подключение ко всем
  создающим маршрутам.
- Код ошибки конфликта в `ERRORS.md`.
- Тесты, заметки о неочевидном.

## Обзорные проверки

1. Два `POST /api/v1/tasks` подряд с одним `Idempotency-Key` и телом создают одну задачу; оба ответа одинаковы, включая ключ задачи.
2. Тот же ключ с другим телом отвечает `409` с кодом конфликта идемпотентности.
3. Два токена с одним ключом создают две задачи.
4. Тест на гонку: десять параллельных запросов с одним ключом создают одну задачу, остальные получают тот же ответ.
5. Повтор выпуска токена возвращает тот же секрет.
6. Ключ старше срока жизни не мешает новому запросу с тем же значением создать новый объект.
7. Полный набор тестов зелёный; `docker ps` чист после работы.
