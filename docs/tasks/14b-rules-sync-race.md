# 14b. Синхронизация реестра правил должна переживать гонку

- **Блок:** Автоматика
- **Зависимости:** нет
- **Результат:** старт контура с нуля не сыплет трассировками в лог

## Зачем

`sync_rules` заводит строку состояния под каждое объявленное правило. Её зовут три
процесса — API в lifespan, воркер и планировщик в первом круге цикла, — и на пустой базе
они делают это одновременно. Второй и третий получают
`UniqueViolationError: duplicate key value violates unique constraint
"uq_automation_rules_rule_key"`.

Последствия сегодня терпимые: воркер ловит ошибку своим циклом, ждёт паузу и повторяет,
API проглатывает её с записью в лог. Но каждый старт контура с нуля даёт полноэкранную
трассировку в логах двух сервисов, и это ровно тот шум, из-за которого настоящую ошибку
при старте не заметят (выявлено в задаче 14 на живой проверке).

## Объём

- Сделать `sync_rules` устойчивой к гонке: вставка с `ON CONFLICT (rule_key) DO NOTHING`
  либо повтор после `IntegrityError` с перечитыванием существующих ключей.
- Вернуть из неё **фактически созданные** ключи, а не те, которые она пыталась создать:
  сейчас вызывающий код пишет в лог список, который при гонке не соответствует
  действительности.
- Тест на параллельную синхронизацию: два вызова в разных сессиях не должны падать, а
  строк должно остаться по одной на ключ.

## Что учесть

- **Строку исчезнувшего правила синхронизация не удаляет** — каскад унёс бы журнал
  срабатываний. Устойчивость к гонке этого правила менять не должна.
- Порядок «сначала прочитать существующие ключи, потом вставить недостающие» гонку не
  закрывает: между чтением и вставкой успевает вклиниться другой процесс. Нужна
  атомарная вставка, а не более аккуратная проверка.

## Готово, когда

- Контур, поднятый с нуля (`docker compose down -v && docker compose up -d`), не пишет
  трассировок в логи `api`, `worker` и `scheduler`.
- Тест на параллельную синхронизацию зелёный.

## Не входит

Отказ от синхронизации в трёх процессах: она нужна каждому из них — контур поднимается до
применения миграций, и первый успешный заход может случиться в любом.
