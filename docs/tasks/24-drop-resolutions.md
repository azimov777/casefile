# 24. Убрать резолюции, оставить причину закрытия

- **Блок:** Очереди, Воркфлоу
- **Зависимости:** нет
- **Результат:** закрытие задачи не требует выбора из справочника

## Зачем

Резолюция как отдельный справочник и обязательный выбор при закрытии — ручная дисциплина
человеческих процессов. Агенту важен факт закрытия и причина словами, а не позиция из списка.

## Объём

- Убрать справочник резолюций, поле резолюции у задачи, требование резолюции при переходе в
  статус категории `done` и сброс при выходе из него.
- Добавить задаче необязательное текстовое поле причины закрытия; заполняется при переходе в
  `done`, не обязательно.
- Миграция: перенести названия существующих резолюций в новое текстовое поле, затем удалить
  справочник и колонку.
- Убрать резолюции из конфигурации очереди, эндпоинтов, инструментов MCP, схем, фильтров и
  языка запросов.
- Чистка документации, демо-данных и тестов.

## Что учесть при удалении

Общие ловушки — см. задачу 20.

Специфика:

- **Воркфлоу задевается напрямую:** правило «в `done` только с резолюцией» встроено в движок
  переходов. Убрать его аккуратно, не сломав остальные проверки требуемых полей.
- Перенос данных делается **до** удаления справочника, одной миграцией: иначе названия
  резолюций потеряются безвозвратно.
- Проверить правила автоматики и сохранённые фильтры, опиравшиеся на резолюцию.
- Не превращать причину закрытия в скрытый обязательный параметр: она необязательна, и переход
  в `done` без неё должен проходить.

## Готово, когда

- Резолюций нет в API, MCP, схеме БД и документации.
- Задача закрывается без указания причины и с указанием; текст сохраняется и виден в истории.
- Прежние значения резолюций перенесены в причину закрытия.
- Весь набор тестов зелёный, живая проверка пройдена.
